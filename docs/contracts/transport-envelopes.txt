1. Common notation, decoded structure and wire bytes
An object below lists its COMPLETE keys; all are REQUIRED unless explicitly
marked ABSENT-OR-U. '?' means nullable, NEVER optional. Arrays include [] and
empty inputs {}. No additional envelope keys such as success,data,requestId,status,
httpStatus or transport actor claims may appear. HTTP status is outside the body.
Unknown/duplicate keys, invalid UTF-8/BOM, invalid Unicode scalars, missing keys,
wrong types, unsupported version/enum, depth>32 and invalid number lexemes refuse.
JSON accepts insignificant whitespace/key order; fixtures use D02 R bytes (UTF-8,
LF, sorted ASCII keys, final LF). Hashes use D02 C bytes WITHOUT a final LF. No
normalization/trimming of text, Unicode or original line endings takes place.
N=decimal integer 0..9007199254740991, no sign, exponent, fraction or leading zero;
positive counters/card revisions/tickets are >=1, board revision may be 0 on an
empty new board. U=nonzero lowercase canonical 8-4-4-4-12 UUID; general domain U
adds no generation-version requirement. Installation/credential Uv4 follow D01.
H=64 lowercase hexadecimal SHA-256 digits. T=valid Gregorian UTC whole-second
YYYY-MM-DDTHH:mm:ssZ, years0001..9999, no leap second/offset/fraction. Newly sampled
persisted times floor UTC once per transaction; same-second events remain distinct.
Identity={boardId:U,incarnation:U}. Target=null|{cardId:U}|{grantId:U}, selected
by command18. Error={code:string,message:string,field:string?}; code is a stable
nonempty category and message nonempty inert diagnostic text, never proof. field
is a dotted schema field path or null. No stack, paths, token/hash, prose echo,
private recovery handle or arbitrary internal exception in Error. The existing
D01 credential CLI Error has ONLY code,message; do not insert field there.
Conflict={incarnation:U,revision:N,cardRevision:N?,cardId:U?}, EXACT D02 shape;
cardId/cardRevision are both null for board-only conflict, both nonnull for an
existing-card conflict when available. A missing target can use null/null. No
current prose is embedded. Derive current read route from returned cardId and the
selected board; use an authenticated current read to expose current text. Preserve
input and original evidence. A changed incarnation requires deliberate action;
never silently adopt it or read an old card as though it belonged to a new board.

Rights=sorted unique ASCII array from approve,attach,comment,create,edit,export,
grant-admin,history-admin,read,read-own-outcome,restore,review-handoff. Order is
lexicographic; no implied rights. Automation cannot receive approve,grant-admin
or history-admin. kind is human|automation; server resolves actor/kind/rights.
Domain/retained row types, sort orders, byte limits, references and nullable fields
below reuse D02's EXACT definitions, not an independent transport domain model.
This is a type reference, not permission for C02 to implement archive validation.

All other typed command inputs and optional omissions are accepted04/18 and C01's

Attachment transport is multipart/form-data with EXACT two parts named metadata
and file, one each, no extras. metadata has Content-Type application/json and is
the normal attachment command JSON <=16384 bytes. file is raw bytes <=10485760,
Content-Type application/octet-stream; any multipart filename is ignored and never
authoritative (input.name supplies inert display name). Reject duplicate parts,
extra parts, encoded/decoded byte disagreement or incomplete final boundary.
The sha256/length must describe exact raw file bytes before writer admission.
Multipart framing/part headers/file path/bearer are not semantic intent. These

Server independently derives route board/target, registered method/command and
credential actor. Complete frozen canonical intent keys are EXACTLY accepted18:

incarnation=U&fingerprintVersion=1&fingerprint=H, each once, no body; query order
is immaterial. Actor derives from CURRENT credential. Target/command/preconditions
are bound by original fingerprint and retained record, not a newly selected card.
Credentials/prose never go in a URL. These query values are public identity/hash
metadata, not a bearer or permission. Lookup performs no mutation and no replay.

4. Unknown and nonterminal refusal
KnownIdentityUnknown={apiVersion:1,outcome:"unknown",boardId:U,incarnation:U,
 opId:U,actorId:U,fingerprintVersion:1,fingerprint:H,error:Error}.
These identity fields are original immutable evidence, not a claim a row exists.
No command/result/revision/terminalAt/retention/conflict may appear. OUTCOME_UNKNOWN
is the ordinary error; SOURCE_AUTHORITY_UNAVAILABLE labels source-incarnation
lookup at restored destination. HTTP503 for server uncertainty; HTTP200 for a
successful lookup that finds no classifiable original evidence. CLI exit4 in BOTH.
Server cannot invent a trusted actor/hash before authentication/validation; use the
following refusal instead, and client retains original uncertainty separately.

NonterminalRefusal={apiVersion:1,outcome:"refused",error:Error,conflict:Conflict?,
 opId:ABSENT-OR-U}. opId is OMITTED when unavailable; explicit null is INVALID.
When present it is a parsed request/route echo, NEVER identity proof. Other identity,
fingerprint,command,result,terminalAt and revision fields are absent. This family
serves unauthenticated, prevalidation, wrong-origin, read and local failures as well
as refusals concerning lookup. It is never a retained NOT_COMMITTED record.
conflict is null unless safe current conflict details are available. A conflict
response cannot substitute later state into a stored RefusalResult. If disclosure
is unauthorized, do not reveal current identity/revisions/text; use null.

HTTP | nonterminal code/category | ordinary read/provably-unsent CLI exit
400 INVALID_INPUT (syntax/schema/version/route mismatch) | 2
401 UNAUTHENTICATED | 2
403 FORBIDDEN (including origin/current permission denial) | 2
404 NOT_FOUND | 2
409 REVISION_CONFLICT / INCARNATION_CONFLICT / OPERATION_MISMATCH | 2
413 INPUT_TOO_LARGE | 2
503 UNAVAILABLE | 3 (only before submission/read)
no HTTP INVOCATION_OR_IO | 1 (provably before dispatch)

An adapter MAY emit refused/HTTP4xx without a terminal record when authentication,
strict decode or complete semantic identity cannot be established. Once authority
can record an identity-bound terminal refusal it uses section3; if recording is
uncertain it cannot assert noncommit. HTTP4xx, error.code, echoed opId, conflict,
missing row, cancel, restart or absent current effect never proves noncommit.
For EVERY lookup failure (including local selector/evidence failures), or a mutation
that may have transmitted without exact terminal proof, CLI exit4 overrides the
ordinary table. A client with valid original evidence may synthesize the exact
KnownIdentityUnknown plus the concrete error (e.g. UNAUTHENTICATED, OPERATION_MISMATCH,
CREDENTIAL_DISABLED), preserving original actor/hash. With no validated complete
original identity, JSON emits NonterminalRefusal with the concrete error and exit4;
it cannot manufacture KnownIdentityUnknown fields. The exit and dispatch context
must be retained by caller; refused is never evidence of original noncommit.
Read/local invocation errors have no opId unless one was parsed. --json emits one
envelope and LF, no prose; diagnostics are stderr. Never dump unsafe received bodies.
