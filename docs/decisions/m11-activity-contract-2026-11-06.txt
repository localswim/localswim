M11.01 SELECTED BOARD ACTIVITY READ CONTRACT
2026-11-06 | M11-ACTIVITY-R1 | #0151

Read committed activity for the selected board through the existing host, actual
CLI and ordinary browser. The result is a bounded inspection of retained facts.
It neither reconstructs missing events nor proves any notification or suppression
decision. Persistent checkpoints, monitoring, alert delivery and changes to write,
restore, pruning or retention behavior are outside M11.

1. Request and authority

GET /api/v1/boards/{boardId}/activity?incarnation={incarnation}
GET /api/v1/boards/{boardId}/activity?incarnation={incarnation}&from=...&through=...
GET /api/v1/boards/{boardId}/activity?incarnation={incarnation}&cursor=...

These are the three query forms, independent of parameter order. The path and
incarnation use existing canonical nonzero lowercase UUID validation. A GET has no
body. Reject malformed encoding, unknown, repeated or empty parameters, a cursor
combined with bounds, and a single bound without its pair. Raw query limit: 4096
bytes; cursor limit: 2048 ASCII bytes, unpadded base64url payload and tag separated
by one dot. Use existing boundary refusals for aliases, methods, encodings and
transport/authentication violations. Valid activity responses are JSON and no-store.

The interval is (from, through], in canonical UTC whole seconds
(YYYY-MM-DDTHH:MM:SSZ, valid calendar values with year 0001-9999). For the first
page with no explicit bounds, sample server UTC truncated to seconds as through,
and set from to through minus seven days (604800 seconds). Explicit bounds must
have 0 < through-from <= 604800 seconds and through <= the sampled server UTC
second. A continuation gets both bounds from the cursor; it does not resample or
move them, even if the clock steps back. No client supplies revision or high-water
values. Invalid first-page bounds produce 400 INVALID_INPUT.

Route through boardapi's ordinary read path in both existing compositions:
local.Runtime's selected-board boundary for standalone/workspace and the existing
T01 boundary where composed. Preserve each composition's ordinary browser and CLI
auth channels, origin/fetch checks, no-store, and CSP. No native-owner shortcut,
disk CLI fallback, cross-board fan-out or cursor-based authorization. The request
boardId and incarnation must match the credential's current selected board and
the snapshot's board row. Resolve current mode/actor/grant and, in the same reader
transaction that projects the page, revalidate the credential (including time and
board/install/origin binding), enabled grant, durable read right and workflow
permission via the shared ordinary grants admission. Run this check before looking
at continuation semantics. No read-own-outcome, mutation, export or history-admin
right substitutes for read. No client-supplied actor identity is trusted.

2. Success wire shape

ActivityRead = {apiVersion: 1, scope: "activity", result: ActivityView}
ActivityView = {identity, from, through, revision, localEventUpper, coverage,
                events, nextCursor}
Identity = {boardId, incarnation}
ActivityEvent = {origin, eventId, at, type, boardRevision, actorId, actorKind}
ActivityCoverage = {status, activityFloor, gaps}
ActivityGap = {origin, reason, fromExclusive, throughInclusive}

All fields required; no extras. identity and origin use Identity. from, through,
at, activityFloor, fromExclusive and throughInclusive use the timestamp format
above; activityFloor and fromExclusive are nullable. revision, boardRevision
and localEventUpper are nonnegative exact JS-safe integers; eventId is positive
in that same range. actorId is a canonical UUID or null; actorKind is exactly
human, automation or unknown. coverage.status is complete, gapped or expired;
gap.reason is cleared or expired. events/gaps are arrays (use [] when empty).
nextCursor is the opaque cursor string or null. One response: at most 20 events,
32 distinct projected gaps and 32768 UTF-8 bytes including JSON formatting.
Strictly validate the transport envelope and page invariants before display,
including selected identity, bounds, event order, limits and enum membership.
Use the shared transport model/Go validator and regenerate schemas and TS types
through internal/contract/transport/generate.go. No parallel browser-only model.

Admit only the committed activity table's current types: card.create, card.edit,
comment.add, attachment.add, attachment.detach, link.add, link.remove,
review-handoff, approve, grant.create, grant.revoke, history.clear,
retention.set, workflow.edit and recovery.expire. The last is a real committed
internal event without an operation ID. Refused, conflicting and replayed requests
add no inferred rows. An unsupported/malformed candidate event makes the page
unavailable; dropping it could create false completeness. Use no join to operation
payloads or current cards. The allowlist intentionally omits affected references,
operation IDs, actor labels, titles, descriptions, comments, attachment names,
paths, grant IDs, workflow labels, hashes and secrets. Render text, never markup.

Selected identity is the containing store's board/incarnation. Event identity is
(origin.boardId, origin.incarnation, eventId). Copy each row's origin and original
boardRevision, even when restored. Do not rewrite them to the selected identity or
compare a source revision/event ID with the destination's counters. For attribution
join the authoritative actor by (selected incarnation, stored actor_id): restore
preserves actor records in the destination namespace, independent of event origin.
Use human/automation only for one valid matching actor record of that stored kind.
With missing, ambiguous or unrecognized kind use unknown; keep a syntactically
valid recorded actorId, otherwise use null/unknown. Never infer from actor label,
op presence, current owner/grant or caller mode. Authority for the requester is
separate from fallback for historical attribution. A query/scan failure still
means unavailable; it cannot be treated as a successful unknown lookup.

3. Capture and continuation

In one store reader transaction establish authority and read the exact selected
board row, its revision and next_event, activityFloor, applicable gaps and rows
with actor facts. First page captures revision and localEventUpper = next_event-1
in that snapshot, as well as the chosen timestamp window. Keep only activity
in the selected incarnation with from < at <= through. For events whose origin
equals the selected identity require eventId <= localEventUpper; the captured
store revision and selected snapshot cover retained rows. This excludes later
commits even with same or earlier timestamps. Finish/close the reader before
writing the response; a failed read/cleanup cannot emit a partial success.

Newest first by the entire tuple (at DESC, origin_board DESC, origin_incarnation
DESC, event_id DESC), using binary comparison of canonical timestamp/UUID strings
and numeric event_id. Continue strictly below the last emitted tuple. Query up to
21 eligible rows to detect the next page; emit 20 and a nextCursor only when the
extra row exists, otherwise nextCursor is null. Do not use OFFSET, client-side
sorting, a global eventId comparison, or a partial tie-breaker. No snapshot or
cursor table is held between requests. Use the existing bounded reader deadline.

Sign a versioned, activity-specific cursor using a process/handler-local key and
epoch (the existing search HMAC machinery may be reused with domain separation).
Bind the exact selected board/incarnation, current mode/actor/grant, captured
revision/localEventUpper/from/through, an applicable coverage fingerprint, and the
last event tuple. The key/epoch are private; grant or installation binding may be
in a digest, not clear cursor payload. Never put credentials, tokens, private
paths or prose inside the cursor. Treat it as opaque, replayable for this exact
unchanged inspection, and meaningful only after current authority checks.

After current admission, re-read revision, local high-water and coverage in the
continuation snapshot. Reject wrong binding, changed revision/high-water (even if
the new mutation falls outside the window), changed applicable coverage, invalid
signature, or host restart with 409 CURSOR_STALE. Structurally malformed/oversized
queries or cursor encodings are 400 INVALID_INPUT. A valid old cursor passed with
another board's own valid selection/credential is stale; an unauthorized selection
is an authority refusal and reveals no cursor details. No silent rewind or automatic
retry/rebootstrap of a stale continuation. Start fresh by dropping the cursor and
requesting an initial page. No independent cursor wall-clock TTL is needed.

4. Coverage and failures

Use the selected board activityFloor and only class='activity' coverage gaps in
that incarnation. Ignore other classes. A gap is (fromExclusive, throughInclusive];
null lower means no lower bound. Include it if it is nonempty and intersects the
request: gap.throughInclusive > from and (gap.fromExclusive is null or
gap.fromExclusive < through). A nonnull equal-endpoint gap is empty. Preserve
original origin/reason/bounds, even when a gap only partially intersects; no clipping
or rebasing. Return distinct projected tuples sorted ascending by origin.boardId,
origin.incarnation, fromExclusive (null first), throughInclusive, reason, using
binary canonical strings. Read at most 33 distinct projected tuples; overflow,
invalid evidence or failed query makes the page unavailable, never a truncated
"complete" page. Fingerprint the canonical selected activityFloor and ordered
applicable projected gaps. If newly read coverage crosses the size cap on a
continuation with otherwise matching revision, treat it as changed and stale.

Use expired when a nonnull selected activityFloor reaches or exceeds through
(selected retention floor covers the entire interval). Otherwise use gapped if
activityFloor > from or any applicable gap exists, and complete otherwise. A
restored expiry gap is evidence about its own origin; it makes the selected
interval gapped, without treating the source floor as a new destination floor.
The floor is not a row filter; available rows can coexist with either incomplete
status. Coverage describes the whole interval and repeats on each page. It speaks
only to recorded coverage, not historical reconstruction, clock correction,
unrecorded pre-restore facts or completeness beyond this inspection.

HTTP 200 complete plus zero events and no cursor means complete empty ("No
activity in this interval"). Zero events with gapped/expired still means incomplete
evidence. An expired interval has a distinct label from a partly gapped one. Keep
the incomplete label when retained rows are shown. Do not map unavailable to a
success envelope: return the existing bounded NonterminalRefusal, 503 UNAVAILABLE
for reader/validation/coverage failure. Existing 401 UNAUTHENTICATED and 403
FORBIDDEN cover failed current authentication and read/scope refusals. Never emit
partial rows, cursor or raw storage/network diagnostics on refusal. Clients must
distinguish malformed or unreachable responses from a valid empty page.

5. CLI and browser behavior

CLI: localswim --data DIR [--json] activity read [--from UTC --through UTC | --cursor TOKEN]
CLI: localswim --workspace DIR --project PROJECT --board BOARD [--json] activity read ...

Use ordinary selected CLI credentials and core read invocation for one page per
command. Populate incarnation from the resolved selection and validate the echoed
identity and page invariants, including canonical bounds and window length, on
every page. When the first request supplies explicit bounds, compare both echoed
bounds exactly. The server enforces the exact bounds carried by a continuation.
The CLI treats that cursor as opaque and has no prior page state. Reuse the
current read exit/refusal conventions. Readable output
names selection, interval and coverage, includes event origin/key, type, time,
revision and recorded actor kind/ID, and offers the cursor when present. JSON
success is the shared envelope; retain bounded machine refusal and stderr
conventions. Help shows an initial read, next-page copy and fresh read without a
cursor. Neither mode queries storage directly or writes a board/receipt.

Browser: a small read-only Activity entry in the selected board. Default to the
server's recent window. Show selection, interval, coverage, retained origin and
actor kind/ID, plus deliberate Next page (only with cursor) and Start fresh.
Keep the inspection scoped to installation/board/incarnation and current session
generation; cancel or ignore pending responses on close, fresh read, selection,
authority change or a newer request. Late results must not replace the active
view, even on A→B→A. Validate page identity, known continuation bounds and
envelope invariants; treat a mismatch as unavailable. Clear stale continuation,
require deliberate restart, and keep drafts, edit focus and private input intact.
No polling, background alert work, raw response logging or new CSP exception.

6. Executable acceptance oracles

S1 Scope/admission: in two synthetic boards (including distinct incarnations),
assert exact selection with authorized CLI and browser credentials. Attempt wrong
board/incarnation, another actor/grant, native-owner-only and no-read grants,
expired/revoked credentials and workflow-disallowed read. Include revocation after
page one and after outer authentication but before snapshot admission. Assert no
events/coverage/cursor from refusals. Preserve origin/CSP and mixed-auth refusals.

S2 Pagination: make >=21 eligible events spanning equal timestamps and overlapping
origin-local IDs in a restored destination. Include both exact interval endpoints,
events outside the window and at least one source event above destination high-water.
Assert exact sorted tuples over all pages, no duplicates/skips and null final cursor.
Commit a new event after page one with at inside the capture; old continuation is
409 without rows, new first page reflects the newly committed event. Exercise
malformed/oversized, tampered, foreign and pre-restart cursors, plus unchanged replay.

S3 Data/coverage: assert one known human, one known automation and a controlled
missing/invalid attribution case; assert historical origin/revision unchanged and
no prose or secrets. Cover complete empty, a floor exactly at from vs through,
retained rows plus a gapped interval, gapped empty, restored expiry evidence,
touch-only/degenerate and other-class gaps excluded, and pruning after page one.
Change relevant coverage without changing revision in a controlled fixture and
assert stale. Force read/validation failure and 33 distinct applicable gaps and
assert unavailable. Include admitted internal recovery expiry; refused/replayed
operations do not contribute extra rows. Confirm the read itself conserves state.

C1 Actual CLI. Use the built binary through standalone and workspace selection
on two synthetic boards. In readable and JSON modes, exercise first/next/fresh
reads, an exact-bound read, complete empty, retained rows with gapped coverage,
and expired coverage. Distinguish malformed input and malformed or unavailable
responses from successful coverage results. Compare parsed tuples and coverage to
the authoritative page. Verify current refusal, a stale pre-restart cursor,
deliberate reopen, and absence of excluded fields from stdout and stderr. Check
that reads conserve both boards' committed state and create no operation receipts.

B1 Ordinary browser: open the actual host on two synthetic boards. Delay a first
or next response for A, switch to B (and repeat A→B→A), release A's old response,
and assert no old events, coverage or cursor is painted. Repeat invalidation on
authority change, and keep unsaved input intact. Assert same facts as actual CLI
for the same selection/window, exact ordering across pages, distinct incomplete,
expired, unavailable and complete-empty labels, plus fresh read after stale/restart.
Use controlled fixtures/clock for coverage and late responses when necessary;
authoritative product assertions determine pass. Use the shared queue only for
bounded sanitized evidence per docs/runbooks/localpost-development.txt.

Q1 Qualification: on the exact candidate run the current pinned gates, two
isolated clean builds and applicable reproducibility checks; bind source, tools,
binary and embedded assets. Run mandatory native/real-browser inventories and
fresh joined activity evidence S1-S3/C1/B1. Identify ordinary vs controlled cases;
record exact binding and justification for any permitted prior evidence. Retain
cleanup receipts and obtain fresh independent review before packaging.

D1 Extracted kit: verify manifest and payload checksums, extract the exact qualified
executable to a fresh location, and use the delivered guides with synthetic runtime
data outside the kit. Make human and automation changes on two boards, compare
their exact selection/attribution/coverage in CLI and ordinary browser, page and
reopen deliberately. Show separately labeled incomplete evidence in both clients,
including how any controlled setup was made. Close owned browsers, processes,
listeners and queue mailboxes; bind fresh demo evidence and review to the kit.
