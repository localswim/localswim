M16 — FIXED PRIVATE RECIPIENT POLICY
November 7, 2026 | M16-RECIPIENT-R2 | Configuration-only model

1. Outcome and authority

Configure one private fixed recipient/policy for one selected physical board,
then reopen and inspect exactly that binding. Saving never activates delivery,
changes a local inbox target, creates a notice/briefing/receipt, grants future
effect eligibility, invokes an adapter or alters existing notice originals.
Every fresh configure request after binding refuses, including identical input.

M16 ships only recipient configure/status. Probes, capability answers, Stop for
native probes, Send/Start/Enable, external receipt lookup, reconfiguration and
retargeting remain later milestones. Existing local notices controls remain.
The original combined M16.01 model is frozen here in full, including the future
probe/lifecycle rules below. Those rules are design constraints, not shipped
operations or qualified native capabilities.

Go remains authoritative. Both clients use the same selected-board HTTP seam.
Require the current installed Human/browser or Bot/CLI principal, exact physical
installation/board/incarnation and current read/disclosure grant through the
same native-selected admission used by existing local notice controls. No caller
actor, grant, installation, native path, policy override or cached authority is
accepted. Saving this private preference confers no future effect/disclosure
authority; those are checked again at every future admission.

2. Exact input and representation

Private input is strict UTF-8 JSON, at most 1,024 bytes, exactly:

{"version":1,"recipient":{"kind":"codex-thread","threadId":"00000000-0000-4000-8000-000000000016"},"policy":"conservative-metadata-v1"}

The UUID is synthetic. threadId is exactly 36 lowercase ASCII characters in
canonical RFC UUID form, with version nibble 1-8 and RFC variant 8/9/a/b. This
accepts current UUIDv7 chat references as well as UUIDv4 fixtures. It accepts no
session name, URL, command, path, argument, whitespace or alternative spelling.
Syntactic validity does not prove target existence, ownership or permission.

version is exactly integer 1; kind and policy are the literal strings above.
No omitted/null/extra/duplicate/case-variant keys, noncanonical integers,
unsupported versions, BOM, trailing values or invalid Unicode are admitted.
Whitespace/property order is ordinary strict JSON; values are not normalized.

conservative-metadata-v1 denotes the existing conservative local-notice intent:
only complete nonempty all-automation evidence suppresses; Human, mixed,
unknown, other, empty, loss and unavailable evidence remain conservative.
The future content is the bounded safe original notice metadata/fallback,
never card prose, credentials or arbitrary caller text. This is saved intent,
not implemented external monitoring or an accepted delivery guarantee.

3. Private durable record and identity

Use a separate recipient-policy.json beside existing native runtime metadata.
Do not change notice-runtime.json v4, local targetId/configurationRevision,
notice delivery identity, SQLite layout, archive/API/fingerprint version or
existing local controls. Native account+SYSTEM ACL, regular single-link file,
non-reparse ancestry, native root lease and physical checks remain mandatory.

The new private format is integer 1, bounded at 4,096 encoded bytes. It contains
only: version, binding, configurationRevision, configurationGeneration,
requestId and input. binding contains the existing native root/database file
keys plus installationId, boardId and incarnation. Account binding is enforced
by current native ownership/DACL checks, not a caller-supplied account field.
Validate every field and binding before use; unknown/legacy/corrupt/foreign
records refuse without projection, migration, repair, truncation or write-on-read.
No old recipient format exists, so unsupported versions are unavailable.

configurationRevision is exactly 1 for a bound record, 0 when unconfigured.
configurationGeneration and requestId are generated canonical UUIDv4 values.
The first is the immutable durable binding generation; the second identifies
the original single save. Both remain exact through reopen. A separate random
runtimeGeneration is regenerated with the engine lifetime, fences current
requests and is never confused with the persistent configuration generation.

Only native not-exist on an initially unopened record means unconfigured. An
already observed record disappearing/changing during this engine lifetime
fences the store unavailable. Missing/unsafe/unreadable native roots, uncertain
cleanup, broken bindings and corrupt data never become unconfigured. A cold
absence alone is not proof that a prior uncertain original had no effect; the
client retains that original uncertainty and never automatically resubmits it.
Current-account out-of-band tampering is not an authorized replacement channel.

4. Save-once publication, concurrency and uncertainty

Status obtains a current-authority/physical-bound read and exact record facts.
Configure first reserves one in-memory operation, checks current authority and
physical identity, and validates runtimeGeneration and expected revision 0.
Recheck actual native state before first publication. A bound record refuses
CONFIGURATION_FIXED even for equivalent content or a repeated requestId; no
idempotent mutation replay or hidden retarget path is provided. A stale context
refuses CONTROL_STALE. A concurrent owner/control request refuses CONTROL_BUSY.

Encode a complete validated record before native publication. Enforce total
capacity before any write. Use the existing private native create-new staged
file, exact full write, file Sync, actual Close and write-through atomic publish;
the final record is created without replacement. Recheck physical and current
authority before returning private facts. Never hold a short memory mutex over
native/SQL I/O. Engine request ownership remains held until native work drains.

A native publication/cleanup error or lost post-admission authority/cancellation
is OUTCOME_UNKNOWN, not a proven refusal. Keep the exact attempted record/hash
and latch a guard; no second configure is allowed in that engine. A pure status
read may inspect the one exact attempted durable record under fresh current
authority. An exact positive match establishes saved configuration, without
republication. Absent/foreign/changed/unreadable bytes keep unknown/unavailable;
they do not authorize retry. Known failed pre-admission parsing/authority/CAS
has no configured effect. Do not call a late admitted write a no-effect refusal.

Original client correlation is deliberately bounded, not a new durable delivery
journal. The CLI freezes one requestId/input/context for its invocation and
retains the explicit input file unchanged. An ambiguous exit reports the fixed
safe UNKNOWN outcome, not private input or a new correlation-output format;
there is no crash-durable retention promise. Once invocation-local correlation
is lost, a later plain status cannot claim to settle that old original. The
browser retains the draft and original request/context
in bounded private per-window/per-identity memory through navigation A-B-A,
failure and late replies. It does not write private recipient values into the
existing window-reference index or promise reload/crash-durable new drafts.
At most 20 contexts with 1,024-byte input each are retained; refuse new pending
admission rather than evict unresolved originals or violate the existing caps.

Reload/close/host reopen, current empty values, a new requestId, another window
or restore cannot establish an old original's non-effect or trigger a POST.
When original correlation has been lost, status reports current saved facts
only and does not claim to settle that old original. An exact positive saved
requestId/input/identity may settle a retained original; otherwise it remains
unresolved. A pending browser original permits read inspection only, never a
new Save/rekey/retry. There is no automatic mutation on restore/reconnect.
This reconciles original UNKNOWN/no-replay with the existing window-lifetime
notice-draft scope without inventing an unpriced durable client journal.

Read/save reservation state machine

- idle -> reserved(status) or reserved(configure) via a short memory gate.
  Both own ALL mutable native seen/present/digest/attempted bookkeeping and
  authority/physical checks exclusively until completion. No native status
  read overlaps a publication or another read; a competing request gets a
  redacted CONTROL_BUSY, not cached private facts.
- A status reservation checks authority/physical identity, inspects bounded
  native bytes and validates complete binding, then rechecks authority and
  physical identity before exposing facts. It never writes/repairs/settles by
  publication. A valid exact attempted record may establish saved facts while
  any outstanding cleanup/unknown latch continues to prohibit another save.
- Configure performs strict input/CAS/current-state checks while reserved.
  Immediately BEFORE invoking any staged-file creation/publication, recheck
  current authority, physical binding and context cancellation. This is the
  write-admission boundary. Set attempted record/hash and guard before entering
  native write I/O, not after an error. All failures from that boundary onward
  are UNKNOWN, including revocation/cancellation after it; no safe refusal is
  manufactured from a possibly completed write.
- Successful full native publication plus fresh post-I/O authority/physical
  checks publishes configured immutable facts. A native/error/cleanup or late
  authority failure returns UNKNOWN without private facts and preserves the
  guard. A later pure exact inspection may confirm saved bytes, never replay.
- Every completion releases only the reservation under the short gate. That
  gate is never held over SQL/native I/O. closing refuses new reservations,
  waits admitted requests and retained cleanup to actually join, then closed
  releases native ownership. A failed join retains ownership and incomplete
  close; memory snapshots do not bypass admission or native bookkeeping.

Runtime close first fences request admission, drains all admitted handlers and
retained native cleanup, then releases store/native identity ownership. Failure
to actually close a native handle retains the lease and an honest unavailable
close result. No worker, timer, child process or delivery is created by M16.

5. Complete HTTP, generated and production-TypeScript seam

GET selected /api/v1/boards/BOARD/recipient/status?incarnation=INC has exactly
that query and no body. POST .../recipient/configure has no query and strict
application/json, bounded at 2,048 bytes, exactly:

{incarnation,expectedRuntimeGeneration,expectedConfigurationRevision,requestId,input}

incarnation uses existing selected identity validation; runtimeGeneration and
requestId are canonical UUIDv4; expectedConfigurationRevision is integer 0.
input is the exact validated object in section 2. requestId is client-created
once before submission and retained as the original identity, never regenerated
by a transport retry. The private record keeps that exact ID.

The bounded response, at most 4,096 bytes, is {apiVersion:1,scope:"recipient",
result:{identity,runtimeGeneration,state,reason,configurationRevision,
configurationGeneration,requestId,input}}. state is unconfigured/configured/
unavailable/unknown; reason is null or storage/foreign/unknown. For unconfigured,
revision is 0 and durable fields are null. Configured has revision 1 and every
valid durable field. Unavailable/unknown return no private input/generation/
requestId and revision 0; they never masquerade as unconfigured. No enabled,
ready, delivered, probe result, native path/account or raw error field exists.

Reuse current strict boundary/Host/Origin/CSP/auth/no-store/media/JSON rules.
Unauthenticated/denied/stale/foreign response handling discloses no private
binding. Post-admission unknown uses a fixed safe OUTCOME_UNKNOWN envelope with
no facts, rather than a partial configured response. Unsupported route/method,
body size, malformed content, fixed/stale/busy/storage/unknown are distinct safe
bounded outcomes. Public logs/diagnostics contain codes only, never threadId,
input, raw received objects/errors or credentials.

Go types/validation/schema/declarations and actual production TypeScript
validation agree on exact fields, nullability, identity, enums, UUID and byte
bounds. Shared vectors cover every refusal and maximum encoding. Complete
current config seam review must PASS before either client. Material client-found
seam changes return here for correction and fresh independent seam re-review.

Exact client result matrix, shared by CLI and browser

- POST success requires HTTP 200, the strict recipient envelope, configured
  state, revision 1, valid durable generation and EXACT submitted selected
  identity, expected runtimeGeneration, requestId and complete input. Structural
  validity alone is insufficient. Only then report this original save confirmed.
- HTTP 200 unconfigured/unavailable/unknown, mismatched scope/identity/runtime/
  request/input, malformed/truncated/oversize/unexpected body, transport loss,
  cancellation after dispatch and output/validation failure are UNKNOWN. Keep
  the original; do not downgrade it to refusal or clear its draft.
- Only strict fixed nonterminal-refusal envelopes with status/code pairs
  400/INVALID_INPUT, 401/UNAUTHENTICATED, 403/FORBIDDEN,
  409/CONTROL_STALE, 409/CONTROL_BUSY or 409/CONFIGURATION_FIXED establish this
  attempt's pre-admission refusal. The server emits those only before write
  admission. Every other POST result, including generic 5xx, remains UNKNOWN.
  A refused new attempt does not settle a different earlier unknown original.
- GET status is current observation. It may confirm a retained original only
  when selected installation/physical scope/identity, requestId and full input
  match exactly and revision/generation are valid. A new runtimeGeneration after
  genuine host reopen is permitted for THIS fresh authorized GET; it is not
  permission to accept an old POST response or automatically resubmit anything.
- Readable and JSON CLI outcomes use identical admission/correlation/exit rules.
  After denied/current-authority loss, no late response republishes private
  facts even if it otherwise has a matching original identity.

6. Actual CLI and ordinary browser

With existing explicit --data or --workspace/--project/--board selection:

  localswim [SELECTORS] recipient configure --input PRIVATE-SYNTHETIC.json
  localswim [SELECTORS] recipient status
  localswim [SELECTORS] --json recipient status

Configure accepts no stdin/path search/env/default reference or arbitrary flags.
Read only the explicit bounded regular private file and validate before HTTP.
GET current status, create one requestId, and make at most one POST. Refuse a
bound/guarded context locally; Go repeats authoritative admission regardless.
Readable/JSON configure success and status name saved-but-not-activated state,
exact authorized reference/policy/revision/generation. Unknown POST remains
exit 4 with empty intentional private payload and bounded safe diagnostics;
nonterminal refusals use existing exit conventions. Never retry the POST or
read live storage directly. Existing local notice CLI grammar is unchanged.

The ordinary browser has a Recipient policy panel, private draft and deliberate
Save once control. Show the exact authorized saved policy and explicit
"Saved; delivery is not activated" wording. Read/Save refuse stale selection,
authority, incarnation and generation. Preserve draft/focus/window/board scope
through input, failure, UNKNOWN and late A-B-A responses. Compare monotonically
fenced request epochs, not board name alone. Recheck current authorization before
publishing private results; clear denied saved facts but retain safe user input
under the current private recovery policy. No Save/Start/Enable/Send/probe is
performed on opening, reconnect, retry of a read, navigation or host reopen.

7. Full future probe/native-lifecycle model — not implemented in M16

The frozen design provider is server-qualified native codex.exe. Its server-only
resolver accepts an ordinary trusted native installation, validates canonical
absolute path, no wrapper/reparse/unsafe replacement, installed provenance and
exact file identity/hash, and pins them for that engine. PATH may discover a
candidate for qualification; it is not authority to run an arbitrary same-named
file. Recheck the pinned identity immediately before launch. No caller path,
argv, shell, wrapper, environment, endpoint or token is accepted.

The exact frozen argv allowlist is identity ["--version"] and capability
["queue","--help"], with closed stdin and a server-owned private working
directory. No prompt, recipient or payload is supplied to either probe. Use a
frozen necessary native environment, never caller-provided environment or a
background idle authority refresh. M17/M18 must qualify that the actual literal
invocations remain read-only and satisfy this model; an unavailable real probe
is a readiness issue, never permission to substitute a fake executable.

Freeze parser contracts now: identity accepts one complete bounded known
publisher version line with ASCII semver (maximum96bytes), optional one terminal
LF/CRLF, zero exit and no unexplained output. Capability accepts a complete
qualified version-specific queue-help grammar advertising text input and UUID
thread selection, zero exit and no unexplained output. It is not a substring
search in arbitrary help/prose. Later qualification pins exact grammar/vectors
and the actual executable; changed/unrecognized output is unsupported/unknown,
never a permissive parser fallback. Raw captured bytes never enter a result.

Future safe result schema (design-only; not generated/exposed in M16), <=2,048
encoded bytes, exactly: {version:1,identity,runtimeGeneration,
configurationGeneration,probeGeneration,kind,state,code,toolVersion,capability,
joined}. UUID generations are canonical UUIDv4; configurationGeneration is the
exact saved binding generation. kind is identity or capability. state is
supported/unsupported/unavailable/unknown/incomplete. toolVersion is null or
the exact validated ASCII semver; capability is null or "queue-text-uuid".
joined is a boolean reflecting actual root/descendant/pipe/handle join.

Only supported/OK with joined=true may have validated positive fields. An
identity result may contain toolVersion but has capability=null and makes no
policy-ready claim. A capability result may name queue-text-uuid only after the
distinct qualified literal help result; it proves advertised syntax only, not
target existence/ownership/effect permission/receiver acceptance/delivery.
Unavailable/unsupported/unknown/incomplete disclose no private target, raw
output or raw error, and positive fields are null. Current-authority or selected
identity loss returns a redacted safe refusal rather than a result view.

Frozen finite code mapping:
- supported/OK: complete actual qualified result and actual joined closure.
- unavailable/TOOL_MISSING or PLATFORM_UNQUALIFIED: no native invocation.
- unsupported/TOOL_UNSUPPORTED or PARSE_UNSUPPORTED: present actual tool or
  complete output does not match the frozen qualified interface/policy mapping.
- unknown/EXIT_FAILED, PARSE_ERROR, OUTPUT_LIMIT, TIMED_OUT or CANCELLED:
  attempted invocation did not produce complete admissible positive evidence.
- incomplete/DRAIN_INCOMPLETE: root/descendant/pipe/handle cleanup not actually
  joined; retain native ownership/exclusion and publish no positive fields.
- CONTROL_BUSY, CONTROL_STALE, FORBIDDEN, UNAUTHENTICATED, IDENTITY_CHANGED and
  CLOSED are safe pre-admission/control refusals with no result/private fields.
  Late denied facts remain redacted; they never become successful receipts.

Actual installed support and useful policy mapping require later ordinary
evidence. No version/help result is receiver permission or delivery/no-effect
proof; no arbitrary fallback probe can turn unknown into supported.

The complete native design bounds are frozen NOW, before dependent storage:
one current probe/physical board, zero queued automatic probes, maximum16active
native job processes including root, 64KiB combined stdout/stderr capture,
10seconds command deadline, then at most2seconds foreground drain reporting.
After that soft drain bound report incomplete and retain ownership until actual
join; the bound never authorizes dropping a descendant/handle or releasing a
lease. Control admission is a nonblocking short-gate reservation, not a wait
behind native output/I/O. These design protocol ceilings require actual later
qualification; they are not adopted D01 fleet/support budgets or measured SLA.
M17/M18 revalidate/qualify this full frozen bundle before the FIRST actual
product probe. A material changed bound/model requires fresh review/estimate
reconciliation; safety cannot be deferred to a later feature phase.

Create the Windows root suspended, assign an owned non-breakaway job with
kill-on-close and the active-process ceiling, establish explicit root/descendant
and inherited-handle ownership before resume, then drain both pipes concurrently
with strict byte/UTF-8/parser bounds. Timeout, overflow, partial output, parser
error, cancellation, parent exit, competing owner or cleanup failure cannot
orphan descendants or release native ownership before actual joined closure.
Failed pre-resume assignment kills/joins the suspended root. A root exit is not
descendant join: require active job count zero, root wait completion, pipe drain
completion and actual close of every owned handle before joined=true. Bound
capture while draining; exceeding output budget terminates the owned job and
retains incomplete status until actual join. Only the fixed codes above publish.

Stop/Close validates current authority, exact identity/control generation and
one admitted operation; it requests termination/drain and honestly reports
incomplete until root/descendants/handles are actually joined. Do not wait on
native I/O under a short memory gate. Denied/stale late results are redacted;
close/navigation/generation changes invalidate unconsumed eligibility. Future
external effects additionally require current effect AND private disclosure
authority, session/run one-use reservation and durable attempted fencing before
invocation. UNKNOWN retains original target/cuts/payload/receipt and no replay.
No idle background permission renewal or interrupted/reopened eligibility exists.

8. Acceptance matrix and evidence gates

- Ordinary: actual private save/read/reopen and exact persistent generation/
  revision/reference/policy, both default and configured boards; local notice
  state/originals/targets/cuts/receipts/acceptedAt unchanged and no child spawned.
- Fixed: different and identical fresh replacement requests, same requestId,
  stale revision/runtime generation, concurrent save/read and competing native
  owner; exactly one binding, no replacement, no duplicate effect.
- Private storage: maximum encoded bounds; missing-initial versus lost-observed,
  legacy/unknown/duplicate/malformed/oversize/corrupt data, foreign account/root/
  database/incarnation, unsafe links/reparse/DACL and storage failures. No repair.
- Uncertainty: pre/post-publication faults, short write/flush/close/rename error,
  lost response, cancellation/revocation after admission, pure exact positive
  status inspection, guarded absent/different bytes and no automatic replay.
- Cross-layer: real Go HTTP and generated plus production TS validators, strict
  bounds/null/enums/UUID/identity and safe refusal/unknown/redaction at every seam.
- Clients: actual CLI readable/JSON on both boards; ordinary real Chrome retains
  draft/focus and selected-window scope through failed/denied/delayed A-B-A,
  conflicting and ambiguous responses. Separately label controlled fixtures.
- Lifecycle/conservation: handler/native cleanup actually joins before releasing
  root; no config data in board JSON/ZIP export/restore/diagnostic/public output.
  Restored independent incarnation starts unconfigured rather than importing a
  source's private destination; a copied foreign sidecar refuses. Preserve all
  accepted archive/restore/original-UNKNOWN/local monitor guarantees.
- Delivery: full CURRENT inventories/two clean builds/ALL outputs, fresh independent
  High source/authority/concurrency/evidence review, exact allowlisted ZIP and
  new extracted ordinary-browser AND actual-CLI default/configured demonstration.
  Preserve failures and owned cleanup. Proposals are reviewed before later Q01;
  no new numerical/behavior decision is adopted here. Terry keeps Completed.

Model review PASS precedes any dependent storage code. Complete config seam
