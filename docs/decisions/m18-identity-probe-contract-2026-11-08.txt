1. Authority, scope and incorporated complete model

M18 epic #0244 and M18-KICKOFF-R2 govern. M18.00 #0321 passed a fresh complete
baseline and independent review. The current execution authorization permits
reviewed dependent progression through RFR; Terry retains Completed.

This contract incorporates M16-RECIPIENT-R2 section 7 and the COMPLETE
M17-INSPECTOR-R3 sections 2-6. Every installation ACL/owner, canonical ancestry,
junction/file pin, primary-signer/provider-state, strict detached/no-child,
atomic job, handle, capture, deadline and actual-join requirement remains.
No weaker native profile, alternate installation, wrapper or caller parameter is
introduced. M17 metadata inspection remains a separate unchanged observation.

M18 enables only literal ["--version"]. Capability is M19. No queue/help probe,
recipient effect, Send/Enable/Start, target replacement, transport/nudge,
shared-host operation, watcher, background discovery or idle authority renewal.
Managed installation metadata is not executed identity. Current qualification
uses the owner-selected unchanged installation; the product is not pinned to a
particular version string. Actual compatibility remains M18.03 work.

2. Selected context and recipient prerequisite

Server context is the exact installation ID, physical root/database identities,
board ID/incarnation, immutable runtime generation, saved configuration
generation, current credential/principal/read authority and server request/operation context.
Client window/view epochs and request-sequence fences are local browser/CLI
correlation guards, not authority values supplied by routing or native admission.
They are not added to the frozen wire. Routing, native claims and current Go admission supply these, never request actor
fields, board labels, PATH or a saved UI observation.

Actual identity operates only with a currently readable, positively bound M16
recipient policy. configurationGeneration is its exact saved UUIDv4. An
unconfigured, unknown, foreign or unavailable policy cannot authorize a process.
The ordinary existing M16 configure-once workflow is unchanged. Both default-
workflow and configured-workflow demonstrations deliberately set up the existing
private policy before actual probing. Metadata-only inspection still works
without it. No recipient value is passed to the process or new protocol.

3. One board slot and one-use generations

Use ONE shared native-operation reservation per physical board for metadata
inspection AND actual probing. There is zero automatic queue. Control/status
reads do no native installation inspection and cannot launch a process. While
metadata inspection owns the shared slot, probe-control and probe-version refuse
CONTROL_BUSY with no probe view; probe Stop refuses CONTROL_STALE and cannot
cancel metadata inspection. Its own request cancellation and internal Close
retain their existing behavior.

The server creates one cryptographically fresh available probeGeneration per
runtime. A deliberate control-status read exposes it only under current selected
authority/configuration. A probe-version POST must match that exact available
generation. Reservation consumes it atomically. While work is active, a second
POST refuses CONTROL_BUSY; an old consumed generation refuses CONTROL_STALE.
After complete actual join, replace the available generation before another
admission. Never intentionally reuse a generation; entropy failure makes new
admission unavailable rather than falling back or retrying a launch.

Keep at most the current operation, the next available generation and ONE joined
tombstone (context/generation/join fact only). A new reservation discards the old
tombstone. No version/output cache, durable probe journal, history, pagination or
lookup of older operations. Repeated old POSTs cannot launch again. A repeated
Stop can observe/request cleanup of the same current operation or the one joined
tombstone; it never becomes another command.

4. Current authority cancellation and ownership

Admission, native preparation, immediately-before-CreateProcess, immediately-
before-ResumeThread and final disclosure require fresh current authority,
configuration and physical context checks. Do not touch browser idle expiry in
these checks. The native check is not cached permission.

Bind the active operation context to request cancellation, runtime Close and
observed authority/credential/configuration/physical-scope loss. There is one
active-only invalidation worker, no idle worker: serial current checks at a
100 ms target interval, at most one check in flight. Failure/denial/change
cancels the owned operation; it never renews authority or retries a process.
A slow native/SQL check is not a bounded SLA: native command expiry independently
requests whole-job termination, and ownership remains until the check and all
native work actually join. Tests must exercise revocation during held work.

Reserve/update memory bookkeeping only under the short nonblocking gate.
SQL, file, path, hashing, trust, directory, wait, termination and Close I/O occur
outside it. Retain an independent admitted-work/physical-board lifetime after
the HTTP handler or view ends. No successor overlaps retained work.

5. Candidate and private run custody

The actual engine independently uses the R3 resolver; Inspect cannot populate
its chosen candidate. On its first qualified actual attempt, retain a private
engine fingerprint of the exact canonical release/file identity/SHA256.
Each later attempt freshly qualifies/opens the candidate and compares it with
that fingerprint. A change invalidates it without automatic rebinding; return
redacted IDENTITY_CHANGED and require a new runtime for a newly chosen candidate.
No raw path/hash/account/signer/environment appears in a public result.

Retain canonical/junction/manifest/executable/trust custody throughout actual
native work; recheck the pinned identity, bytes and security immediately before
creation/resume and before disclosure. No pathname-only check/use launch.
A known changed native or physical identity cancels work and redacts its facts.

Create an account-private, server-owned per-runtime/per-probe work root using
the verified token/profile and existing native private-directory primitives,
outside archived board/SQLite/recipient data. A fixed agent-neutral local
application runtime subtree is allowed; no caller or ambient HOME/TEMP path
selects it. Use fresh exclusive leaves, non-reparse pinned ancestry, exact
account/SYSTEM private ACL and no inherited input/configuration/credentials.
The contained home/appdata/temp/CODEX_HOME and fixed system-only environment
follow R3. Root identity and ownership are retained through cleanup. Refuse
collisions and unsafe paths; do not repair ACLs or collect another run's bytes.
Safe cleanup must not traverse child-created reparse escapes; qualify this with
an external canary. Interrupted stale directories never grant resume eligibility.

Native root/job/pipe/handle custody is R3 without exception: suspended root,
atomic JOB_LIST, DETACHED_PROCESS, restricted child policy and verified exact
mitigation bits before resume, explicit inherited stdio list, closed stdin,
16 TOTAL process ceiling including console/out-of-job helpers, concurrent
65536-byte combined capture, ten seconds FROM RESERVATION and at most two
additional foreground cleanup-reporting seconds. Unrestricted diagnostic
helpers remain separately labeled; they cannot qualify a selectable production
profile or the installed tool.

6. Actual join, Stop and Close

joined=true requires root wait, actual job count zero, both drains complete,
the invalidation worker joined, all run-owned process/thread/job/pipe/file/trust/
directory handles closed and run cleanup resolved. No outstanding quarantined
resource, numeric-handle retry or ownership release is allowed. Native job
supervision closes last after zero-process evidence. Ambiguous Close poisons
that owned object; retain the slot/physical claim without replaying Close.

Stop is a fresh authorized request for the exact runtime/configuration/probe
generation; installation/physical/board/incarnation come from current routing.
Stale/foreign/denied Stop cannot affect another operation. Valid repeated Stop
requests the same cancellation and bounded join observation, never a new launch.
Fresh SQL/native authority admission is not claimed to complete within two
seconds. Once Stop admission is valid and cancellation is requested, its native
join observation has at most two foreground seconds. Expired/disconnected
admission cannot later cancel anything: recheck request context and the exact
current tuple after the checks and before the short control gate action. Each
started check retains runtime/request lifetime until it actually joins, even if
the caller has timed out; Close cannot release storage/physical ownership early.
A client admission/response timeout confirms neither cancellation nor join and
never causes automatic retry. An incomplete operation keeps its generation and exclusion. Stop of the one joined
tombstone is idempotent and discloses no captured version.

Close first fences admission, cancels active work and tries actual join.
Incomplete Close remains incomplete, retains native/engine/physical ownership
and prevents a replacement runtime. Process exit is not a false in-process
join. View closure/disconnect may cancel only its own admitted request; it must
not issue an automatic control against another view's operation.

7. Exact selected-board HTTP grammar

Existing exact Host/Origin, credential/cookie, no-CORS, no-store and CSP boundaries
remain. No board revision CAS is needed: this work changes no board state.

GET /api/v1/boards/{boardId}/recipient/tool/probe-control
  ?incarnation=UUID&expectedRuntimeGeneration=UUIDv4
  &expectedConfigurationGeneration=UUIDv4
Exactly these three unique query keys, raw query<=384 UTF-8 bytes, no body.
It verifies the saved configuration and current authority, then returns:
{apiVersion:1,scope:"identity-control",result:{
 identity:{boardId,incarnation},runtimeGeneration,configurationGeneration,
 probeGeneration,phase,joined}}
phase is ready/running/draining. ready has the available one-use generation and
joined=true (engine quiescence, NOT proof that that generation ran). running or
draining has the current generation and joined=false. No installed-tool facts.

POST /api/v1/boards/{boardId}/recipient/tool/probe-version
POST /api/v1/boards/{boardId}/recipient/tool/stop
No query. Exact JSON object, <=512 UTF-8 bytes:
{incarnation,expectedRuntimeGeneration,expectedConfigurationGeneration,
 probeGeneration}
All required; no null, duplicate/unknown keys, Unicode/BOM/trailing JSON tricks,
alternative spelling, caller kind/path/argv/environment/recipient or retries.

Probe-version returns the DIRECT frozen result in section 8, <=2048 UTF-8 bytes.
Stop returns <=2048 bytes:
{apiVersion:1,scope:"identity-stop",result:{
 identity:{boardId,incarnation},runtimeGeneration,configurationGeneration,
 probeGeneration,phase,joined}}
phase is joined/incomplete and exactly agrees with joined true/false. It echoes
the requested current/tombstone generation, not a newly available generation.
A joined Stop is no identity/version success or proof the original request was
cancelled before execution.

All responses are application/json and Cache-Control:no-store. Reject unexpected
encoding, redirects, malformed framing, wrong type, oversize, unknown/duplicate
keys and mismatched identities/generations in Go, generated schema and actual
production TypeScript validation. Limits are inclusive encoded UTF-8 sizes.

Use existing exact NonterminalRefusal (no opId, conflict:null, error.field:null,
fixed message Request refused, no private/native details):
400 INVALID_INPUT;401 UNAUTHENTICATED;403 FORBIDDEN;
409 CONTROL_STALE/CONTROL_BUSY/IDENTITY_CHANGED;503 UNAVAILABLE.
405 INVALID_INPUT/404 NOT_FOUND retain existing routing behavior.
No bound/available policy yields 503 UNAVAILABLE before reservation.
Known authority loss redacts facts even after successful execution. If final
authority cannot be established inside foreground reporting, return safe
UNAVAILABLE, not stale/native facts; retained work remains owned.

8. Frozen result, parser and outcome precedence

Exact direct probe result (all fields required, no extras/null except specified):
{version:1,identity:{boardId,incarnation},runtimeGeneration,
 configurationGeneration,probeGeneration,kind:"identity",state,code,
 toolVersion,capability:null,joined}

All generations are canonical UUIDv4; identity uses existing strict Identity.
supported/OK requires joined=true and exact actual toolVersion, strict ASCII
SemVer2.0.0 (max96 bytes; no leading-zero numeric identifiers). Accept exactly
one stdout line "codex-cli "+SemVer, optional ONE final LF or CRLF, empty stderr,
zero exit, complete capture and actual join. The executed version must agree
with the freshly qualified package manifest version; mismatch is
PARSE_UNSUPPORTED, never repaired metadata or a new candidate.

Other exact pairs have toolVersion:null and capability:null:
unavailable/TOOL_MISSING or PLATFORM_UNQUALIFIED, joined=true;
unsupported/TOOL_UNSUPPORTED or PARSE_UNSUPPORTED, joined=true;
unknown/EXIT_FAILED, PARSE_ERROR, OUTPUT_LIMIT, TIMED_OUT or CANCELLED,joined=true;
incomplete/DRAIN_INCOMPLETE,joined=false.
kind never accepts capability in M18. No generic supported/ready verdict.

Precedence: denied/changed context is redacted refusal; otherwise any unjoined
work is DRAIN_INCOMPLETE regardless of another cause; after actual join retain
the first authoritative cancellation/deadline/native failure; only a clean
native OK, exit0 and complete exact parse can become supported.
Native CREATE_FAILED/EXIT_UNKNOWN or incomplete preparation evidence maps to
unknown/EXIT_FAILED after full cleanup, not a fabricated process exit fact.
A proven unsupported native profile/qualified-installation policy maps to
TOOL_UNSUPPORTED. Unavailable cached revocation, absent/ambiguous provider state,
wrong/unprovable verified-signature selection or other INSPECTION_UNKNOWN
preparation evidence is NOT definitive unsupported policy: after actual cleanup
it maps to unknown/EXIT_FAILED, or TIMED_OUT when deadline was the first known
cause. Any unjoined cleanup instead remains DRAIN_INCOMPLETE. None launches a
process or exposes positive fields. Complete well-formed but unrecognized output is
PARSE_UNSUPPORTED; malformed/partial encoding is PARSE_ERROR. Raw output/errors
never leave the private bounded worker. API/CLI unknown/incomplete never enables
automatic replay.

9. Ordinary clients and original preservation

Existing explicit --data or --workspace/--project/--board selection:
  localswim [SELECTORS] [--json] recipient tool status
  localswim [SELECTORS] [--json] recipient tool probe-version
  localswim [SELECTORS] [--json] recipient tool stop --probe-generation UUIDv4
Existing recipient tool inspect remains metadata-only and unchanged.

Status is one deliberate control read with current saved context. Its valid
ready/running/draining response exits0; only probe-version's preflight rejects
running/draining locally as CONTROL_BUSY. Stop must accept an active slot,
subject to its exact generation and fresh authority checks. Probe-version
obtains current M16 status and one control status, then makes ONE POST. No native
attempt if policy is not positively bound or the slot is not ready. Stop obtains
fresh selected context and submits the explicit generation once; the server
still requires the exact active/tombstone tuple. Status is not an automatic poll.
Readable/JSON share the same parser/admission/results. JSON stdout is one exact
validated response; never raw installed stdout. Use this operation-specific table:

Phase / observed response                         Exit / public interpretation
Local syntax/selector/body-encoding failure        1 INVOCATION_OR_IO; no POST sent
Status control GET200 ready/running/draining       0 exact validated control view
Probe-version pre-GET200 configured/ready           continue to one start POST
Stop pre-GET200 positively bound configuration     continue to one Stop POST
Any command pre-GET200 unbound/unavailable policy   3 UNAVAILABLE; no native POST
Probe-version pre-GET200 running/draining slot      2 CONTROL_BUSY; no start POST
Pre-POST GET strict recognized refusal             2 exact fixed code; no new POST
Pre-POST GET transport/body/framing/context error  3 UNAVAILABLE; no new POST
Probe POST200 valid supported/OK/joined             0 exact frozen result
Probe POST200 valid unsupported/unavailable        3 exact frozen result, no version
Probe POST200 valid unknown/incomplete             4 exact frozen result, no version

Stop POST200 valid incomplete                      4 control incomplete, no version

mismatched/oversize/redirect/encoding/IO/context   4 OUTCOME_UNKNOWN, no native facts

The recognized GET pairs are exactly section7, including503/UNAVAILABLE.
The recognized POST pairs are those same fixed pairs EXCEPT503 (always unknown).
Never reuse M16/notice helpers that infer native non-execution from a strict
refusal. A native POST403/409 refusal can occur after admission/execution:
exit2 means current disclosure/control was refused, NOT that no process ran,
that an earlier attempt had no effect, or that native custody joined. No POST
refusal is an execution receipt. Local/GET 'no POST' refers only to this client
invocation, never another operation or prior unknown request.

When no validated operation result/control response exists after POST, emit
the dedicated client-only JSON unknown envelope:
{apiVersion:1,outcome:"unknown",
 error:{code:"OUTCOME_UNKNOWN",message:"Identity check outcome unknown"}}
It has no result, opId, identity/generations, version, joined assertion or private
fields. It is not a server ProbeResult and cannot fabricate DRAIN_INCOMPLETE.
Register/validate this exact envelope and safe readable diagnostic consistently.
Client-side current authority loss clears observations; no raw response or
captured request facts are republished. All paths retain one-submit/no-replay.
Valid status0 proves only a current control observation, not a command result.

The ordinary browser adds Check installed version and Stop check to the existing
recipient tools panel, with named keyboard controls and honest pending/result
states. Missing policy keeps the new action unavailable with existing configure
guidance. A user gesture reads current context/control once and starts once.
Opening, navigation, reload, reconnect and background refresh never start/status-
poll/probe/Stop native work. Stop uses its captured current operation generation;
view closure aborts only its own request. A late A-B-A or old connection response
cannot paint facts or clear a newer pending state/draft/error. Denied context
clears old observations, preserves safe existing drafts/originals under current
policy, and never rekeys or settles an uncertain M16 save.

Display a version only after validated supported/OK/joined. Other outcomes say
missing/unsupported/unavailable/could not complete/still stopping as appropriate,
not success or delivery readiness. A fresh ready status proves only quiescence.
A lost native result has no recovered positive version; a new check requires a
new deliberate gesture and fresh one-use generation, never replay of the old POST.
No version persistence, Copy, new recipient selector, credential or activation.
