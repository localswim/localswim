# #0584 T2 independent technical review

## Initial findings

- **Board stylesheet.** The native `user_css` value is validated and never used by the renderer. A configured board therefore opens with the default styles. The observation ledger assigns this rendering to #0584, and the OpenAPI contract says the stylesheet applies while the board is open under the existing CSP. Verify one visible rule on a configured board and its removal when switching to another board. See [read.ts](../../web/clean-room/board/read.ts#L101), [render.ts](../../web/clean-room/board/render.ts#L329), [observation ledger](0582-observed-contract.md#historical-inventory-mapping-and-remaining-observations), and [OpenAPI](../openapi.yaml#L16146).
- **Read retry after concurrent recovery.** The supplemental reads can reject on a changed user or priority registry before the final board revision check executes. For example, a native restore can commit between the lane view and the users list. If that changes membership, the users-list count or ID guard rejects the result, and the one-retry path never observes the revision change. Recheck the revision before committing to a supplemental-response failure, while retaining the existing bounded retry and abort behavior. Exercise a changed collection followed by a coherent full read. See [read.ts](../../web/clean-room/board/read.ts#L221), [read attempt](../../web/clean-room/board/read.ts#L340), and [native recovery](../../internal/v2/snapshots.go#L77).
- **Keyboard focus after node removal.** `restoredFocus` remembers the logical control even when the DOM no longer has focus. On a keyboard Retry, loading hides the focused Retry button. A second failure makes it visible again, but the saved logical target still matches and the renderer skips restoration. A focused card moved between lane lists also loses its DOM node and cannot restore by identity. Restore after an update displaces focus inside the board, while leaving focus outside the board intact. See [lane/card reconciliation](../../web/clean-room/board/render.ts#L192), [focus restoration](../../web/clean-room/board/render.ts#L286), and [read-state rendering](../../web/clean-room/board/render.ts#L329).
- **Board retention during reconnect.** The selected-board Retry refreshes workspace setup. A session, service, or catalog failure then routes to the workspace and disposes the selected board, even when the root retains its confirmed data. Keep the addressed board selected and render the confirmed data as unavailable while reconnect fails. See [board props](../../web/clean-room/main.ts#L73) and [workspace refresh](../../web/clean-room/main.ts#L166).
- **Rank and triage numeric bounds.** The native initial workflow accepts a nonnegative Go integer rank without a JavaScript-safe upper bound. A rank of `100000000000000` is itself JavaScript-safe, but the first card at that rank has a native triage score of `10000000000000100`. The unused triage value then rejects the whole board read. Align the fields that do not require exact JavaScript arithmetic with the native contract, or bound them coherently at the source if that contract changes. The native board view already supplies card order. See [native workflow input](../../internal/v2/custom_workflow.go#L97), [native card creation](../../internal/v2/cards.go#L283), and [read validation](../../web/clean-room/board/read.ts#L129).

## Verified by inspection

- The V2 lane view supplies native card order. The renderer preserves it within each lane and arranges lanes by position. Active lanes and cards have keyed DOM nodes. Lane captions derive from move grants and honor actor label overrides. Priority and ticket indicators use their native data, and zero-comment cards hide the comment badge.
- The read adapter validates resource identity, ownership and membership before publishing assembled board data. It permits native archived hierarchy targets and retired-lane registry references outside the lane view. Existing tests cover paging, revision rollover, foreign policy and native unavailability.
- The root aborts an obsolete read and retains confirmed data per selected board. The workspace disposes the prior board instance when selection changes. Board listeners share an abort lifetime and are removed on disposal. Board and lane scroll are reported separately, and saved offsets are restored when a board remounts.
- The Architect approved native UUID values in the V1 `/board/<key>` route shape. Review uses that interpretation of the presentation-route requirement.

## Correction review

- The selected board now mounts inside its own shadow root with a same-origin baseline stylesheet. A constructable sheet applies the confirmed board's `user_css` in that root, including when confirmed data is retained during a failed refresh. Clearing the CSS unadopts the sheet. Switching boards aborts the old listeners, unadopts the sheet, and removes its host. The baseline load and error paths release the initial visibility gate and restore scroll and focus. The browser CSP remains unchanged. See [mount and styles](../../web/clean-room/board/render.ts#L108), [stylesheet update and disposal](../../web/clean-room/board/render.ts#L361), and [browser asset route](../../internal/v2/browser.go#L11).
- The stylesheet is isolated by selector scope. It can style the board host with `:host`, and custom positioning or overflow can paint beyond the host's rectangle. Constructed sheets ignore `@import`. The board supplies `.lane` and `.card` hooks for board content. This review does not establish a full mapping for historical CSS selectors or styles targeting the surrounding workspace.
- The UI Lead reported a browser check with a configured 4 px lane outline on Alpha, default styling in the surrounding workspace, and no adopted sheet on Beta after switching. That evidence covers one local rule and disposal on selection change. The baseline request's error path releases the board without baseline styling. Neither that asset failure path nor arbitrary CSS combinations were independently exercised in this source review.
- The collection adapter now distinguishes an invalid page from well-formed membership that differs from the opening view. The latter triggers the final revision check. Source tests cover changed and stable revisions. If a restore replaces the policy UUID, the adapter now holds the opening policy's 404 until that same revision check, retries after a revision change, and preserves the 404 at a stable revision.
- Rank and triage validation now accept rounded JavaScript integers in unused display fields. The adapter no longer treats two parsed ranks as a duplicate because Go can emit distinct integers that round to the same JavaScript Number. The focused source test covers that case.
- The renderer now queues restoration when a focused owned node is hidden or replaced. An external focus event cancels the pending request. This corrects the identified Retry and cross-lane replacement paths by inspection.
- The root now resolves the addressed board against its retained catalog on failed workspace setup. It aborts a pending board read and supplies the confirmed board as unavailable when the address still identifies a catalog entry.

Source inspection used the fresh TypeScript and CSS, native V2 implementation and OpenAPI, and the rendered V1 evidence and observation ledger. The UI Lead owns the browser comparison, integrated checks, and final candidate verification.
