Material findings

R1 High - Refused targets need not denote an existing entity
Location: docs/contracts/archive-recovery-schema.txt:194-228, especially 227-228;
compare 140-150 and accepted03 Atomic admission and outcomes / accepted04 Errors.

The requirement that ALL operation target references resolve a full entity,
tombstone or historical fact excludes a legitimate retained NOT_COMMITTED result
for an attempted mutation of a never-existing card or grant. Accepted admission
records validation refusals, and NOT_FOUND is an accepted refusal. The attempted
target remains part of the immutable fingerprint even though no target row ever
existed. Manufacturing a tombstone would invent provenance and contradict :150.

Correction criteria:
- Distinguish an attempted NOT_COMMITTED target from a committed effect/reference.
  Preserve its exact submitted UUID and terminal evidence without requiring a
  fabricated entity, granting authority or weakening committed-reference checks.
- Add exact full and compact NOT_FOUND examples with an unresolved attempted
  target; show source-archive preservation after restore. Include a contrasting
  broken committed-reference rejection. No runtime execution is required here.

R2 Medium - The tampered-BLOB negative never reaches its digest check
Location: fixtures/contracts/archive-recovery/verify_fixtures.py:180-189;
negative/tampered-blob.bin; negative-cases.json case "blob hash mismatch".

The verifier first parses EVERY negative as JSON. The raw Evidence B bytes raise
JSONDecodeError at :181, so the tampered-BLOB branch at :187 is unreachable for
this fixture. The reported eleven rejected cases therefore do not demonstrate
the stated negative digest predicate. Independent raw-byte comparison confirms
that these bytes differ from the protected note digest, but the supplied verifier
does not perform that check on this case.

Correction criteria:
- Dispatch this binary case before JSON parsing and compare its raw bytes with
  the declared note digest/length. Assert the intended mismatch explicitly.
- Keep parser/schema negatives separate from binary negatives, preserving exact
  binary bytes and the documentary-only qualification boundary.

R3 Medium - Operation byteFacts lacks an exact semantic mapping
Location: docs/contracts/archive-recovery-schema.txt:186-203,225-226,251-258;
fixtures/contracts/archive-recovery/verify_fixtures.py:112-128.

ByteFact has a precise shape/order and repeated lengths must agree, but no rule
defines which facts an operation MUST retain. In particular, an otherwise valid
full attachment.add can declare byteFacts=[] or an unrelated digest while its
hashed canonical payload names the actual attachment digest/length. The protected
union is then computed from the independent declaration. The present positive
fixture happens to agree; neither the contract nor the verifier requires that
agreement. A downstream implementer must invent this cross-field invariant.

Correction criteria:
- Specify exact byteFacts cardinality/content by accepted command. Bind
  attachment.add facts to its canonical metadata and applicable result attachment;
  define the retained compact/refused mapping and its non-pinning behavior.
  State the empty mapping for commands with no byte evidence, or explicitly
  explain any other accepted-source mapping.
- Add documentary semantic negatives for omitted/substituted facts and conflicting
  lengths. Preserve the distinction between historical digest facts and BLOB pins.
