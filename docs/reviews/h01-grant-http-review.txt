Verdict: PASS within the accepted H01 component scope.

The adapter implements only POST /api/v1/grants and DELETE
/api/v1/grants/{grantId}. C02 supplies strict decoding and credential-derived
actor binding. Create requires null target; revoke independently resolves the
stored grant's board and requires exact route/body target equality. G01/S02
retain current authority, exact board revision, null card revision and outcomes.

Reviewed boundary

- T01's common TLS/Host/Origin/preflight/media boundary precedes dispatch.
  The single presented bearer is classified through actual current ordinary
  verification or actual current native-owner verification. A header or token
  shape supplies no principal, replacement credential or administrative rights.
- Ordinary browser/CLI requests recheck current grant/actor/rights in G01/S02.
  Revoked callers cannot recover retained receipts; automation cannot gain
  approve, grant-admin or history-admin. Native ordinary-read rights remain absent.
- The new native snapshot facade holds the native lifetime before a bounded
  query-only S01 reader; actual current owner verification precedes callback,
  actor derivation and scope reads. Callback errors survive successful cleanup.
  Trusted internal callbacks must close Rows and retain no snapshot or seam.
- Observed native submission reuses G02's private preparation/admission and S02.
  HTTP 201 requires this invocation's successful Apply and the exact generated
  grant result/reference in the final full committed receipt. Apply alone or a
  prelookup miss supplies no freshness proof after rollback/reconciliation.
- Matching full/compact receipts, revocations and terminal refusals use 200.
  Preterminal refusals remain distinct; known-identity uncertainty preserves
  exact original metadata. Wrong source, hash, denial or missing evidence never
  proves original noncommit or permits replay. H01 adds no lookup endpoint.
- Root README and provider-facade decision match these component boundaries.
