S04 #0055 credential persistence: fresh independent review
Revision 1, 2026-10-26

Verdict: PASS for the approved private persistence provider. No material findings.
Owner acceptance still gates G02; this review does not complete authentication.

Reviewed scope
- Physical layout 2 stores only credential SHA-256/public metadata. Its UUIDv4
  IDs, canonical exact origin, whole-second UTC times and exact 30-day duration
  have storage constraints; credential metadata cannot be updated in place.
- One row per grant prevents overlap. Unique IDs/hashes span grants. The current
  board/incarnation insert guard and grant/actor composite FK prevent detached,
  historical-only or cross-actor grant bindings. Open audits persisted relations.
- Disabled and expired metadata can remain valid storage. Every authorization
  must check current grant/policy, time and configured installation/origin in G02.
  A syntactically valid origin or digest does not establish runtime authority.
- Exact layout inventory and the prior domain constraints remain intact.
  Layout 1 refuses without migration/adoption, byte changes or inventory changes.
  API, logical archive and fingerprint versions remain 1. Private credential rows
  have no archive/sourceAuthority fields; future export/restore must omit them.

Independent verification
- Go 1.27.3, Windows/amd64, CGO=0, local toolchain, readonly module lock/cache.
- Native storage tests passed count=2: 32 top-level tests and 57 subcases per run,
  zero skips. Fresh synthetic NTFS fixtures included actual junction/path checks.
- Eight additional invalid-input subcases and five top-level adversarial tests
  passed count=2. They cover canonical/temporal extremes, cross-grant binding,
  corrupted actor/current-grant FKs, and read-only refusal after corruption.
- The original preserved layout-1 schema generated the independent legacy
  fixture; reopen refused with identical database bytes and directory inventory.
- Storage vet and diff whitespace checks passed. Reviewed provider source stayed
  identical to the parent's nine-file frozen review snapshot.

The initial native run's two failures were sandbox denial of synthetic junction
creation. Its evidence was retained. A scoped host rerun used fresh fixture,
temporary and build-cache roots and passed; no test was skipped or weakened.

Limits

- No live boards, real grants/credentials, trust stores or installations were
  accessed. Synthetic SQL replacement/persistence is not product authentication,
  recovery, hostile-account or power-loss qualification.
- The independent reviewer changed only this report and private review evidence;
