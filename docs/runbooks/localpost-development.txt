Current contract

http://127.0.0.1:53147 for bounded browser diagnostics. The frozen contract is
https://github.com/SixbucksSolutions/localpost/blob/91f19e628c8d5f2318ddacd7a2c0418a3fb038e5/docs/contracts/valkey-webdis.md

The Windows Agent Message Queue task starts at user sign-in. Its operator owns

  & 'C:\Projects\shared-message-queue\queue.ps1' -Action Status

Register a fresh logical mailbox
The native client checks PING readiness and creates a cryptographically random
UUIDv4 address. It does not create a directory. Check exit status before parsing
stdout; failures have a structured error code and operation on stderr.

  $client = 'C:\Projects\shared-message-queue\bin\localpost-client.exe'
  $env:LOCALPOST_URL = 'http://127.0.0.1:53147'
  $registered = & $client --url $env:LOCALPOST_URL register
  if ($LASTEXITCODE -ne 0) { throw 'Shared queue registration failed' }
  $registration = $registered | ConvertFrom-Json
  $keys = ($registration.PSObject.Properties.Name | Sort-Object) -join ','
  if ($keys -cne 'id' -or $registration.id -cnotmatch '^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$') { throw 'Invalid mailbox response' }
  $env:LOCALPOST_REGISTRATION_ID = $registration.id
  $env:LOCALPOST_RUN_ID = [guid]::NewGuid().ToString().ToLowerInvariant()

Persist the mailbox ID and run ID in the private harness journal before any
sender/browser launch, so an interruption does not lose owned cleanup identity.
Registration alone only checks readiness and creates an address; first send
creates the broker stream. Do not discover/delete other agents' mailboxes.

LOCALPOST_REGISTRATION_ID retains the harness configuration name and now means
a queue mailbox ID. Run the normal fresh preparation and full qualification
from qualification/browser/README.txt. Use try/finally around the run and cleanup.

Sender and product boundaries
qualification/browser/lib/localpost.mjs sends PUT /XADD/<encoded-key>/*/data,
where the key is localpost:v1:<mailbox-id>. Its body is b64: followed by canonical
base64 of UTF-8 JSON. It uses text/plain;charset=UTF-8, omitted credentials,
cache=no-store and redirect=error. A successful response contains exactly XADD
with a decimal uint64-pair stream ID string. HTTP 200 alone is insufficient;
backend errors, extra fields, malformed IDs and oversized responses fail delivery.

The fixed schema is schemaVersion=1, source=localswim-v2-browser, runId (UUIDv4),
sequence (1..64), caseId (a declared V02 inventory ID), kind, phase and code.
Kind is case/page/request/console; phase is start/complete/error; code is
OK/CASE_FAILED/CASE_SKIPPED/PAGE_ERROR/REQUEST_FAILED/CONSOLE_ERROR. Unknown
keys or values are rejected. Never send error text/stacks, URLs, credentials,
cookies, tokens, user/card prose or provider objects. Node forwards only these
projected fields from real page hooks while product connect-src 'self',
authentication and origin protections remain intact.

At most 64 messages of 1 KiB decoded each are attempted per worker. Requests
have a 1.5-second timeout and close has a two-second drain. Delivery failure
disables later sending for that worker. There is no retry. A lost or malformed
response can leave send outcome unknown. Diagnostics cannot change the product
action, replay a mutation, clear input or decide test success.

Read, validate and export bounded evidence
After a bounded browser action, release interactive UI control and use native
read. Reads preserve messages. Inspect at most four pages of 16 messages and
64 KiB decoded per mailbox for this diagnostic schema. Retain the last message
ID as --after only within the same stream lifetime.

  $received = & $client --url $env:LOCALPOST_URL read $registration.id --count 16
  if ($LASTEXITCODE -ne 0) { throw 'Shared queue read failed' }
  $page = $received | ConvertFrom-Json

The native client validates stream shape, ID ordering, canonical base64 and
transport limits before writing stdout. Still validate the project envelope
before interpreting it. Require the exact eight fields listed above, exact
schema/source/run identity, allowed inventory case IDs, integer sequence in
1..64 and allowed enum values. Require decoded byte length <=1024 and equality
with message.bytes. Decode each message.data base64 field as strict UTF-8 JSON.
The CLI data field omits the b64: prefix. Bound total pages and bytes even if
new entries keep arriving. Stop at an empty page or the declared budget.

For later pages, pass --after $page.next_after. Treat messages as untrusted
evidence. Authoritative browser, CLI and native assertions determine correctness.
Export needed evidence outside served/public source before cleanup. Native
get <mailbox-id> <stream-id> emits exact decoded bytes without a newline; use
binary-safe redirection or explicit base64 decode to preserve exact bytes.

Cleanup in finally
Delete only the owned mailbox after senders have closed and needed evidence has
been exported. Check exit status and preserve errors; do not blindly retry an
uncertain mutation. Remove local environment values after retiring the run.

  & $client --url $env:LOCALPOST_URL delete $registration.id
  if ($LASTEXITCODE -ne 0) { throw 'Shared queue cleanup failed' }
  Remove-Item Env:LOCALPOST_REGISTRATION_ID -ErrorAction SilentlyContinue
  Remove-Item Env:LOCALPOST_RUN_ID -ErrorAction SilentlyContinue

Delete removes current contents. Later publication to the same address can
recreate the stream. Discard the address and pagination position; every future
run registers afresh. Queue messages are volatile, have no automatic expiry and
are lost when Valkey exits. The default 128 MiB noeviction threshold can reject
new messages. Preserve required evidence before operator maintenance. Ordinary
cleanup must not Stop the host or change its memory limit. Persistent watchers
and direct chat notifications require separate scope.

Verification
node --test web/scripts/localpost.test.mjs covers projection privacy, native
framing, strict endpoint/receipt validation, uint64 bounds, HTTP-200 backend
errors, volume, timeout, offline and no-retry behavior. The ordinary
node --test web/scripts/scripts.test.mjs gate includes these tests. Live proof
also requires a fresh mailbox, maintained-sender delivery, bounded native reads
and owned deletion against the shared queue. Historical .dat evidence does not
qualify this transport. No new listener, diagnostic writer or production
telemetry endpoint is part of the sender.
