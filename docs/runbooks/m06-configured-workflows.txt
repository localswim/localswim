Configured new-board workflows: native and CLI use
2026-11-04 | M06 backend slice; browser workflow controls and joined qualification remain separate

A configured board has one immutable Workflow definition. Create it only for a
new private board; there is no reconfiguration command. Omitting --workflow on
workspace creation retains the existing four-lane default and its literal lane
names. Ordinary first serve also creates the default profile. A configured board
uses lane UUIDs; its labels do not grant authority.

Prepare a private UTF-8 JSON file containing exactly one Workflow object, with
no wrapper, unknown fields or nulls. This complete synthetic example is valid:

{
  "workflowId": "10000000-0000-4000-8000-000000000001",
  "revision": 1,
  "lanes": [
    {"id":"20000000-0000-4000-8000-000000000001","label":"Queue","role":"initial"},
    {"id":"20000000-0000-4000-8000-000000000002","label":"Working","role":"in_progress"},
    {"id":"20000000-0000-4000-8000-000000000003","label":"Review","role":"review"},
    {"id":"20000000-0000-4000-8000-000000000004","label":"Done","role":"completed"}
  ],
  "transitions": [
    {"from":"20000000-0000-4000-8000-000000000001","to":"20000000-0000-4000-8000-000000000002","actors":["automation","human"]},
    {"from":"20000000-0000-4000-8000-000000000002","to":"20000000-0000-4000-8000-000000000003","actors":["automation","human"]},
    {"from":"20000000-0000-4000-8000-000000000003","to":"20000000-0000-4000-8000-000000000004","actors":["human"]}
  ],
  "actorRights": {
    "human":["approve","create","edit","read","read-own-outcome","review-handoff"],
    "automation":["create","edit","read","read-own-outcome","review-handoff"]
  }
}

Generate distinct nonzero lowercase UUIDs for a new definition and its lanes;
retain the exact file for inspection. Definitions are limited to 64 KiB, 4-16
lanes and 3-64 sorted directed transitions. Actor and rights arrays are sorted and
unique. See the Workflow schema and validation in
../../internal/contract/archive/README.txt and the generated schema at
../../schemas/archive/contracts.schema.json for the contract.

Create and reopen

  localswim --data NEWDIR --json board init --workflow FILE
  localswim --data DIR --json board inspect
  localswim serve --data DIR

NEWDIR must be a new private native target; occupied or partial roots are not
replaced. Inspect returns the validated identity and complete definition, or
omits workflow for the default profile. Serve reopens without a workflow flag.
For an existing workspace and project, the actual CLI also supports:

  localswim --workspace DIR --project PROJECT --json board create --key KEY --label LABEL --root NEWDIR --workflow FILE
  localswim --workspace DIR --project PROJECT --board BOARD --json board read
  localswim serve --workspace DIR

Omit --workflow to create a default workspace board. Registration accepts an
already valid board, not a new workflow:

  localswim --workspace DIR --project PROJECT --json board register --key KEY --label LABEL --root DIR [--expected-identity FILE]
  localswim --workspace DIR --project PROJECT --board BOARD --json board status [--root DIR] [--expected-identity FILE]

The identity file contains installationId, boardId and incarnation. Keep board
roots, workflow drafts, identity files and original operation evidence private.
The workspace and --data selectors are alternatives; do not combine them.

Read and move

Board, card, history, search and hierarchy reads include the complete definition
on configured boards. Use IDs from the selected board's current read. Card create
enters the initial role; its input cannot select a lane. Use the full typed request
and current revisions described in m02-cli-read-edit.txt. For a configured move,
construct a fresh card.edit envelope with input containing only {"laneId":"UUID"}:

  localswim --data DIR --json card move CARD-UUID --input FILE
  localswim --data DIR --json card search --lane LANE-UUID

Workspace-selected domain commands use the same command suffix. Move does not
fetch revisions or retry. It checks the configured edge, current grants and
rights ceiling; entering in_progress also checks blocking prerequisites. Generic
moves cannot enter review or completed. Handoff and approval retain their separate
semantics; only a verified human with current approval authority can approve.
The local CLI is automation and cannot approve, even if a card is assigned to a
human. Completed cards remain read-only. For default boards, search uses the exact
legacy lane literal and the existing start/edit path, not laneId.

Uncertainty and compatibility

A setup result can be UNKNOWN after dispatch. Retain the exact draft, selection
and any known identity; do not automatically repeat creation. Deliberate native
inspect or workspace status is read-only and does not settle an earlier UNKNOWN.
Ordinary CLI workspace status reports registration/identity facts only; it does
not compare workflows or fully validate a registered live root. Use selected
board read for its complete live definition, or native board inspect while the
root is closed/unregistered. Compare that complete definition, including ordered
lanes, transitions and rights, with the retained draft and exact identity; a
matching workflow UUID alone is insufficient. Busy or foreign ownership and
unavailable validation do not prove success or absence.
After deliberate inspection, an initialized but unregistered board can be
registered with the explicit command above. A current read never settles an
UNKNOWN card mutation; follow m02-cli-read-edit.txt for original-outcome lookup.

Physical layout 8 retains base-schema marker 5. Startup does not upgrade older
stores. With the host closed, inspect and explicitly upgrade adjacent versions
5->6, 6->7, then 7->8 as applicable, using exact board and incarnation IDs:

  localswim --data DIR --json storage inspect --board-id BOARD-UUID --incarnation INC-UUID
  localswim --data DIR --json storage upgrade --from-version 7 --to-version 8 --board-id BOARD-UUID --incarnation INC-UUID

See m05-relationships.txt for the earlier adjacent steps and recovery conditions.
Compatible archive version 1 preserves configured definitions; default exports
omit workflow. Older strict decoders may reject configured archives. This guide
records backend and CLI availability, not full milestone or release qualification.
