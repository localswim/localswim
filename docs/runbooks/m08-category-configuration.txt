Read current configuration and counts
  localswim --data DIR --json workflow show
  localswim --data DIR --json attention show

attention show returns one authorized board snapshot with board/incarnation,
board revision, current policy version, profile, implicit/explicit source,
assigned lane IDs/labels/roles and three stateful counts. Known zero means a
configured category currently contains zero committed unarchived cards.
Not configured means its assigned lane array is empty.

Category definitions
Add this optional field to a complete Workflow candidate.
  "attention": {
    "blocked": ["EXISTING-WAITING-LANE-UUID"],
    "needsTerry": ["ANOTHER-WAITING-LANE-UUID"],
    "readyForReview": ["EXISTING-REVIEW-LANE-ID"]
  }
Replace the illustrative strings with IDs from the same candidate. Every array
is sorted by exact ID and duplicate-free. Blocked and Needs Terry accept only
waiting lanes and remain disjoint. Ready for Review accepts its one protected
review lane or an empty array. Initial, in_progress and completed are separate
roles. Category labels and card relationships confer no category assignment.

All three arrays are present when attention is explicit. [] disables that
measure. Omitted attention restores the implicit mapping with only the review
role configured. An explicit mapping equivalent to the implicit one still
records a deliberate change. Null and partial objects refuse.

Preview and save
Follow m07-workflow-changes.txt to construct a complete candidate and retain

  localswim --data DIR --json workflow preview --input preview.json

Inspect the category before/after source and assignments, current/candidate
counts, occupancy, preserved approvals and capacity. Preview reserves no state.

  {"opId":"FRESH-UUID","incarnation":"INCARNATION","target":null,

  localswim --data DIR --json workflow edit --input original.json

Existing grants intersect current ceilings. A successful category or mixed
edit advances board/policy once and retains card content/revisions, approvals
and historical pins. Empty waiting-lane retirement removes its assignment in
the same candidate. Historical definitions retain the old identity and mapping.
A retired ID remains reserved. Invalid, stale and equal candidates retain the
existing refusal/NO_CHANGE rules.

UNKNOWN and recovery
Retain original bytes, opId, fingerprint and selected source. Use the deliberate
operation read/evidence procedure in m02-cli-read-edit.txt. Current attention,
workflow reads, preview, reload and reopen do not settle or replay that original.
A fresh intent follows explicit inspection and reconciliation.

Storage and compatibility
Current storage uses physical10/base5. Stop the owned host before an existing
physical9 upgrade and supply exact expected identity.
  localswim --data DIR --json storage inspect --board-id BOARD-ID --incarnation INCARNATION
  localswim --data DIR --json storage upgrade --from-version 9 --to-version 10 --board-id BOARD-ID --incarnation INCARNATION

Earlier stores retain their explicit adjacent steps. Startup never upgrades.
The 9-to-10 step preserves logical rows, identities, definitions, original bytes
and blobs and advances only the physical marker. Ambiguous completion requires
deliberate inspection. The older physical9 reader safely refuses10.

Exports/restores preserve every retained policy's attention presence/arrays,
historical pins, approvals, complete originals and exact blobs under the
existing documented identity/bootstrap transforms. API/archive/fingerprint
versions remain1. Old absent fields retain their original encoding.
