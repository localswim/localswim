M09 DETACH CARD FILES

Browser

Open the selected card, refresh its files and inspect a current file. Choose
Detach file. Review the file name and UUID, card title and UUID, selected board
and incarnation, and captured board/card revisions. Confirm detach file submits
that exact captured request. Cancel detach file returns to the inspected file.
Retained files have no detach action.

The board base and inspected file revisions must agree before opening the
confirmation. A stale result requires an explicit board/file refresh. The server
rechecks current attach authority, workflow ceiling, Completed role and both
captured revisions. Archived cards follow the same authority rules.

The confirmation uses the existing private editor checkpoint and immutable
submission evidence. Existing changed input must be explicitly retained or
discarded before a new editor replaces it. Submission never refreshes the
captured base. The original result appears under Original operation outcomes.
Pending and UNKNOWN outcomes prevent another dispatch. Look up original outcome
uses the saved identity, operation UUID and fingerprint. Reload restores private
input and original evidence without replaying the request.

CLI

Use the ordinary selected-board CLI context and an original request JSON file.

  localswim [selection flags] attachment detach CARD_UUID --input original.json

The file uses the standard mutation envelope with opId, incarnation, target,
expectedRevision, expectedCardRevision, and input containing only attachmentId.
It carries no attachment bytes. The CLI checks its selected card against target,
freezes and reads back private evidence before dispatch, then makes one POST to
/api/v1/boards/BOARD_UUID/cards/CARD_UUID/attachment-detach. Existing operation
read with the original evidence resolves uncertainty. A second deliberate
operation requires a new opId and independently captured current revisions.

Results

Committed detach removes the current reference and invalidates displayed file
facts. Read current board and refresh files to see the current/retained split.
Retained metadata, bytes, history and original-operation evidence follow their
existing retention rules. Ordinary download requires a current reference.
NO_CHANGE is a durable not_committed result. A lost response remains UNKNOWN
until original lookup supplies authoritative evidence.

Existing storage

Detach uses physical layout11 with base schema5. Stop the owned application
host before upgrading an existing layout10 board. Use its exact saved identity.

  localswim --data DIR --json storage inspect --board-id BOARD_UUID --incarnation INC_UUID
  localswim --data DIR --json storage upgrade --from-version 10 --to-version 11 --board-id BOARD_UUID --incarnation INC_UUID

Earlier layouts retain their individual adjacent upgrade steps. Startup never
upgrades a store. After successful inspection, reopen the normal application
using its saved port. If completion is uncertain, inspect deliberately before
another action. Old layout10 executables refuse layout11 and cannot read a
detach-bearing archive. Existing old-vocabulary archives retain their format.
