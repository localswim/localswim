M09 SAFE ATTACHMENT UPLOAD

Browser
Read current attachment board, choose an Attachment target card, and open its
attachment editor. Active cards is the initial Attachment archive context.
Choose Archived cards explicitly to select an unfinished archived target.
Completed-role cards are excluded using the current workflow definition.
Both the current grant and actor-kind workflow attach ceiling gate the editor.

Select one file and enter its exact display name and media label. Capture owns
one complete in-memory copy before asynchronous hashing. Zero bytes is valid.
The inclusive raw-file bound is10 MiB. Names remain inert metadata. Changing
the file does not overwrite a manually supplied name. A cancelled chooser,
failed read or oversized replacement retains the prior complete captured bytes
and metadata. The captured-source indicator names the complete file and byte
count actually used for upload, separately from editable display metadata. It
changes only after a successful capture and is removed on explicit discard. A pending capture disables
Attach once, and a late older capture cannot replace the newest selection.

Attach once freezes the original board, incarnation, card, revisions, metadata
and copied bytes before preparation. The server rechecks current authority,
workflow role, revisions and distinct protected-byte quota. Private recovery
stores metadata and immutable original evidence. It never stores raw file bytes.

Preparation failure retains editable input. A terminal refusal retains the
editor and blocks unchanged resubmission. Deliberate metadata/file changes can
start a new operation, still against the frozen original context. Explicitly
discard the editor and read/select again to use a fresh context. Refresh never
replaces the editor, selects by ticket or retries the upload. Leaving requires
a confirmed successful submission with unchanged input, or explicit discard.

Stop waiting preserves UNKNOWN. Use Look up original attachment operation for
the exact original context. UNKNOWN never enables a replacement upload.
Navigation, refresh, reopen and another window do not automatically submit or
look up an operation. Forced reload cannot restore raw bytes. An unsent draft
requires deliberate file reselection; preserve its metadata and verify its
name, length and digest before deliberately replacing a different selection.

CLI
  localswim --data DIR --json attachment add CARD-UUID --input ENVELOPE.json --file RAWFILE
  localswim --workspace DIR --project KEY --board KEY --json attachment add CARD-UUID --input ENVELOPE.json --file RAWFILE

The existing complete envelope and positional card must agree. Retain its
opId and canonical bytes for original lookup. Do not infer noncommit from a
lost response or blindly repeat an unknown upload. Duplicate content creates
a distinct attachment ID while protected-byte quota counts its digest once.

Verification
The controlled runAttachmentUploadProbe uses actual DOM/file inputs and the
private recovery pipeline with synthetic delivery outcomes. It checks failed,
cancelled, oversized and out-of-order captures, exact binary/empty bytes,
metadata preservation, composition/Enter, refusal/UNKNOWN navigation guards,
explicit original lookup, archived selection and configured-role ceilings.
It complements native/service/real-browser add, quota, concurrent-CAS, fault
and full export/restore conservation evidence. It does not qualify them alone.
