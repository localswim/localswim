LOCAL BOARD NOTICES IN THE BROWSER

Use the ordinary local board or workspace URL. In a workspace, choose the
board first. Open Notices and choose Read status. Check the displayed board,
incarnation, target, checkpoint and current monitor state before acting.

- Configure creates or returns the selected board's target. Start begins a run.
- Read status reads the current monitor state. Read inbox shows up to 64 retained
  notice receipts, newest acceptance first.
- Look up receipt checks an exact Target ID and Delivery ID from a receipt or
  pending observation. An accepted result shows the matching receipt. UNKNOWN
  means the service could not establish acceptance for that exact pair.
- Stop asks the current run to drain. Stopped, partial drain, guarded uncertainty
  and failure appear separately. Read status before deliberately starting again.

A control uses the generation from a deliberate Read status. Read status again
after each control or lookup before choosing another control. If a control is refused
as stale, read status and decide whether to choose the action again. If the
outcome is UNKNOWN, inspect the new status before deciding how to proceed.
Lookup can reconcile a pending observation. Closing Notices, changing
the board, or losing the current connection clears the view and cancels its
outstanding reads and controls. An in-flight command may already have reached
the service. Inspect status after reconnecting or reopening the selected board.

Notices controls support normal Tab and button activation. Close notices returns
focus to its opener. Notices reads and controls leave the card editor and its
private recovery data alone. For the equivalent native commands see
m12-notices-cli.txt. For development diagnostics see localpost-development.txt.
