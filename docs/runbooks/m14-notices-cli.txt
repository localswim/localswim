M14 NOTICE RELOAD AND RETARGET — ACTUAL CLI

Use the running selected-board service and the same port as ordinary board work.
Standalone prefix: localswim --data DIR
Workspace prefix: localswim --workspace DIR --project PROJECT --board BOARD
Add --json before notices for the versioned API 1 result. Credentials and selection
remain subject to the ordinary installed CLI admission and current workflow.

Routine commands (append to either prefix)

  notices status
  notices reload
  notices retarget --target-id 12345678-1234-4234-8234-123456789abc
  notices inbox
  notices lookup --target-id ORIGINAL-TARGET --delivery-id ORIGINAL-DELIVERY

Use a deliberately chosen canonical lowercase UUIDv4: exactly 36 ASCII bytes,
version 4 and valid variant bits. The target names this board's private local inbox
partition. It is not a filesystem path, URL, Codex chat or external destination.
No registration is required. Configure allocates the initial target; Retarget
requires an already configured monitor. Same-target Retarget is a no-op.

Every mutating invocation, including exact Lookup, reads status once and submits
one POST with that exact control generation and configuration revision. It never
refreshes or retries a stale, busy, timed-out or lost request. Separate CLI
invocations are deliberate new actions. A prior displayed status is informative;
the invocation obtains its own exact preconditions immediately before its POST.

Read the future target and configuration revision separately from Last/Pending
original targets, delivery IDs and cuts. Retarget changes future observations
after confirmed publication. An open observation and immutable pending intent
keep their original target, identity and cuts. Last and accepted receipt pairs
also retain their original target. Exact Lookup uses that original target and
original delivery ID after arbitrary Retarget operations. Its accepted time is
the original local-inbox acceptance time, never an external delivery claim.

Reload retains target/revision and physical ownership. A running monitor drains
old admitted effects before admitting one replacement. A stopped or guarded
Reload stays stopped or guarded. Retarget of a stopped/guarded monitor does not
Start or Recover it. Running Retarget replaces only after a clean drain and
fresh authority. Incomplete control / partial-drain means work remains owned and
reserved; read status deliberately later to observe eventual actual state.

Outcomes and recovery

- Exit 0: confirmed status/control snapshot. Read state and reason: guarded,
  failed/storage or partial-drain is not a clean running result.
- Exit 1: invalid invocation or local setup/output I/O failure before dispatch.
- Exit 2: confirmed pre-admission refusal, including CONTROL_STALE, CONTROL_BUSY,
  CONFIGURATION_EXHAUSTED and current-authority refusal. Inspect current status
  deliberately before deciding on a new action. No silent retry occurs.
- Exit 3: status or service unavailable before notice POST dispatch.
- Exit 4 / OUTCOME_UNKNOWN: the POST may have had an effect. The fixed warning
  says to read notices status before further action. Lost/malformed responses,
  final response-authority denial/failure/deadline and lost output preserve this
  uncertainty. Do not replay the control on the assumption it was refused.

A strict HTTP 503 unknown result is exit 4; a validated pre-admission refusal is
exit 2. The readable and JSON forms carry the same distinction. Diagnostic stderr
uses fixed codes, without raw service errors, credentials, private paths or prose.

After unknown/partial results, status is a new observation, not proof that the
original request was refused. After storage uncertainty, safely stop/reopen the
owned host and inspect validated durable state through the service. Do not edit
sidecar JSON, query SQLite as a CLI fallback or launch a second owner. Follow
m13-notice-recovery-cli.txt for deliberate Recover and exact positive receipt
proof. Recover cannot replay attempted receipt-free uncertain delivery. Start is
a separate deliberate action after a clean stopped state.
