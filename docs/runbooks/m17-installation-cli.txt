M17 — Inspect installation metadata through the CLI

Use the actual localswim executable against an already running selected board:

  localswim --data C:\PRIVATE\board recipient tool inspect
  localswim --data C:\PRIVATE\board --json recipient tool inspect

For an existing workspace member:

  localswim --workspace C:\PRIVATE\workspace --project demo --board work recipient tool inspect
  localswim --workspace C:\PRIVATE\workspace --project demo --board work --json recipient tool inspect

Supply your own exact private roots and registered project/board keys. The two
selection forms are mutually exclusive. No board, installation path, version,
input file, stdin or command argument is inferred or accepted by this action.

Each deliberate invocation authenticates through the existing service, reads
recipient status once for its runtime generation, then sends one bodyless GET
to the selected board's installation inspector. It never runs codex.exe,
inspects the filesystem itself, retries, creates an operation receipt or changes
the saved policy. It works before and after fixed recipient configuration.

Read the result as an observation of the supported installation location:
- Candidate present; no command was run. Current metadata qualification passed.
- No candidate in the supported installation location. This does not rule out
  another installed copy outside that location.
- Qualification not established. A definite policy refusal means only that the
  supported inspection policy did not qualify this installation. UNKNOWN and
  TIMED_OUT mean the inspection could not complete.

The result does not establish an executable version, command interface,
capability, policy readiness, receiver permission or delivery. It grants no
future launch authority. Paths, hashes, signer details and recipient values
are absent from both readable and JSON output.

Exit codes
- 0: a valid candidate, missing or unqualified observation was returned.
- 1: invalid invocation grammar.
- 2: a recognized service refusal, including denied, stale or busy inspection.
- 3: transport, invalid/unusable response or output failure; no usable result.
There is no mutation-uncertainty exit4 for this read.

On stale, busy, unavailable or interrupted output, keep any private editor and
original-operation evidence. A later invocation is a new deliberate observation;
the CLI does not automatically retry or settle an earlier operation. A failed
inspection does not change saved recipient or local-notice state.
