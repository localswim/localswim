## Work

Before ordinary writes, compare the current durable state with the accepted state using the store's existing identity and revision boundary. Report corrupt or independently changed state accurately, refuse replacement of that file and allow explicit repair. Keep checks local to the affected board.

## Demo and acceptance

Test a corrupt snapshot and a structurally valid but divergent replacement at the same revision. Ordinary rename refuses both and leaves the bytes intact while a second board accepts writes.
