## Work

Qualify the write fence with post-replacement fault injection. Keep writes for the affected board fenced until durable outcome is verified or explicitly repaired. Keep another board writable when the failed commit is proven board-local and retain wider fences for uncertain shared state.

## Demo and acceptance

Inject an ambiguous commit into one board, verify the reported uncertainty and continue work on another. Resolve the first board through the supported recovery path.

## Implemented behavior

- A failure settling the recovery reference after snapshot replacement reports
  `503 outcome_unknown`. Export and verification can inspect the saved snapshot
  of an already accepted board. After uncertain creation, restart and inspect
  the original UUID in the catalog before retrying. Further writes refused by the
  fence report `503 unavailable` with `not_applied`.
- The fence stays on the affected board when disk matches a known outcome and
  workspace user definitions are unchanged. Both possible sets of resource IDs
  remain reserved. Creation, uncertain shared users, or an unverified disk
  outcome retain the workspace write fence.
- A fenced board cancels queued owner notices and suppresses new notices and
  backup or automatic publication captures. Unfenced neighbors keep working.
- Restart verifies the snapshot against any pending reference. When neither
  candidate matches, the board stays quarantined and uses the explicit M84
  recovery path. Unsettled evidence alone cannot authorize same-ID recovery.
