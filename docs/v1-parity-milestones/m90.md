## Work

Bound the whole Git process tree, including inherited pipes, with platform-appropriate cleanup. Preserve known local commit and unknown remote outcome evidence, and leave the repository lock reusable after cleanup.

## Demo and acceptance

Stall a disposable Git helper and observe timeout and meaningful status. Verify no helper or held lock remains, then recover the pending publication without creating a duplicate commit.

## Implemented behavior

- Each Git command bounds inherited pipes as well as Git itself. Unix uses a
  process group. Windows uses a kill-on-close Job Object assigned while Git is
  suspended, before its transport helpers can start.
- A stalled push records `git_push_timeout`. The original local commit and
  destination remain pinned because the remote may already have accepted it.
- Cleanup confirms the command and ordinary process-group or job members have
  stopped before releasing the repository lock. Unconfirmed cleanup retains the
  lock and is checked again on a later attempt. Retrying the original destination
  reuses the prepared commit.

## Focused verification

- `TestM90CommandDeadlineContainsInheritedPipes` exercises a stalled process
  tree, a nonzero parent exit with inherited pipes, and a live child that
  closes its standard streams.
- `TestM90UnconfirmedCleanupRetainsRepositoryLease` verifies that another
  publisher can use the lock only after cleanup is confirmed.
- `TestM90UnixKeepsGroupLeaderUntilSignal` verifies the leader remains
  waitable when the process group is first signaled.
- `TestM90StalledPublicationPreservesCommitAndRecovers` uses disposable SSH
  helpers to stall before and after remote acceptance. It checks the durable
  receipt, terminated child, reusable repository lock, exact pending checkpoint,
  and successful recovery with one local commit.
