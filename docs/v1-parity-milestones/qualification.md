[Milestone index](README.md) · [Post-T10 audit](../v1-parity-gaps.md)

Run this walkthrough after the individual milestone checks pass. Budget two hours for the integrated session and evidence review. Use representative fresh V2 data, a disposable Git remote and an authorized test notice recipient.

| Session | What to show |
| --- | --- |
| Workspace and card work | Open the pinned overview and switch among busy boards. Watch a Bot edit arrive. Create a card with files, navigate its relationships and review the work as Human. Lose a save response and inspect the recovered draft and submission. |
| Bot work | Triage across work lanes, inspect a ticket and its relationships, catch up on comments and verify a grouped owner notice using sanitized activity. Repeat read-only inspection and saved activity reporting with the writer down. |
| Recovery and publication | Protect a damaged board, continue editing a healthy board, then recover the damaged one. Restore a portable attachment-heavy backup with the current notice routing preserved. Publish to the configured disposable remote and verify the staged index and ignore safeguard. |
| Windows operation | Launch independently, confirm browser and CLI connection, activate a staged build on the same port and stop with the final edit durable. Review the measured workspace timings and cache bound from [M94](m94.md). |

Link each result to the milestone demo or rerun evidence. Record unmet outcomes as follow-up work and close them before claiming full parity. Once Terry is satisfied with the workflows, he can start new boards in V2 side by side with V1.
