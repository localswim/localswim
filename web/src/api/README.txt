Board HTTP and prepared-evidence boundary

BoardClient.open composes the production IndexedDB driver, W01 RecoveryStore and
boardBoundaryVerifier. Supply installationId/profileId, an ephemeral in-memory
credential getter, and the trusted composition root's ProfileQualification proof.
Qualification defaults to absent. No feature detection or synthetic test assertion
qualifies the product profile; later browser qualification must supply real proof.
Recovery-open failure still permits authenticated reads but refuses submissions.

session reads the credential-bound actor independently. Board/card reads validate
exact generated structural schemas and selected identity. Go remains authoritative
for grants, coherent projections, admission and domain invariants. HTTPS, same-origin
relative routes, no cookies, no redirect following and no-store are required. Tokens
exist only in the Authorization header; no session/credential DTO enters recovery.

submit detaches the caller's input before awaiting, rechecks the current actor/scope,
prepares exact accepted semantic bytes and inserts immutable evidence before its
single initial dispatch. W01 requires strict transaction completion and fresh exact
readback. The concrete prepared verifier rejects unknown/duplicate keys, unsupported
command/target shapes, invalid Unicode/numbers and incorrect semantic/canonical
correspondence. SHA-256 binds those bytes. Optional omissions normalize to null only
inside the semantic payload; original wire text is retained separately.
Nonblank validation uses C01's exact Go Unicode White_Space set, including U+0085
and excluding U+FEFF. This predicate never trims or normalizes the retained text.

The structural schema map in schema-data.ts is generated by the aggregate Go
contractgen command from mutation, transport and archive schemas. It includes
qualified references and participates in the same nonwriting drift check. It is
boundary validation, not another domain/admission model. Boundary tests compare
all ten supported commands with accepted independent semantic-byte vectors;
Go contract fixtures remain authoritative.

Terminal handling binds the original context/opId/hash/command/target/preconditions
through W01 and verifies exact full/compact schemas, terminal class, revisions,
command-specific result facts and result-ID correspondence. Only matching terminal
proof appends classification. HTTP errors, unknown/refused bodies, cancellation,
lookup denial and unavailable evidence preserve unknown. No retry, replay, automatic
confirmation or unchanged-state/text inference exists. lookup loads original evidence
and only GETs its original operation. Loading evidence never authorizes dispatch.

Synthetic component tests use a fresh isolated profile and an explicitly synthetic
qualification assertion. They establish local DOM/IndexedDB behavior and accepted
byte-vector correspondence, not product browser qualification, TLS/session/backend
security, real CLI interoperability, native durability or power-loss safety.

W03 follow-through uses this same prepared verifier and RecoveryStore for
attachment.add, history.clear and retention.set. Recovery confirmation retains
payload={input,previewHash}; card revision/target remain null. Exact full/compact
board result references and attachment raw byte facts remain bound to original
metadata. Retained terminal proof is accepted only with HTTP 200/201 for initial
dispatch and HTTP 200 for lookup; HTTP errors retain uncertainty.

preview validates the exact standalone generated D02 response, original actor,
board/incarnation, command/input/revision and complete canonical preview hash.
The detached preview is held only in memory. Confirmation rechecks current human
history-admin and board revision before freezing that exact original intent.
Loading an earlier recovery submission still permits lookup only.

submitAttachment copies raw ArrayBuffer bytes before its first await, checks
10 MiB, exact length and SHA-256, then freezes metadata through W01 before one
multipart dispatch. The body has exactly metadata/application-json and
file/application-octet-stream parts. Framing and raw bytes never enter semantic
intent or private recovery records. Caller changes cannot change submitted bytes.
Download checks current authenticated metadata and complete raw length/hash
before returning bytes. Export checks exact generated preconditions and receives
the trusted authenticated H02 body with exact MIME, no content encoding, declared
and streamed length and 144 MiB bound. This is no second browser archive-domain
validator. The UI may offer these complete bytes; it cannot verify a local save.

openSessionClient owns its bearer in an ephemeral closure. Exact one-use code
exchange sends only {code} in the JSON body, validates the no-store secret
response, then independently reads the bearer-bound session and complete grant.
No code or bearer is returned to UI, persisted or included in a URL. An epoch
fences exchange completion after clearing/logout. logout captures its bearer,
clears authority and notifies views synchronously, then makes one best-effort
bodyless DELETE; only exact SessionRevoked confirms presented-token revocation.
401/403 clears current authority. Local clearing never classifies an original
mutation. Reauthentication does not rewrite a retained original context or
replace its operation ID, and a different actor/scope cannot look it up.

BoardClient.search reads the separate CardSearchRead boundary. Requests retain
the original Unicode query (maximum 1024 UTF-8 bytes) and exact typed filters;
Go owns all matching. Responses validate generated schema, selected identity,
exact filter/query echo, at most 20 unique ordered summary rows and bounded
continuation. Summaries contain no graph and never qualify as BoardRead/CardRead
or mutation proof. Failed/stale reads throw; callers retain prior rows as stale
and deliberately request a new first page.
